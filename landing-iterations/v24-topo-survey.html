The Traverse

ROUTE LENGTH: 8 STATIONS · BEARING: DATA → DEPLOYED

ML people already talk this way: loss landscapes, decision boundaries, local minima. This sheet takes the talk literally and maps the lifecycle as a survey traverse across that terrain. Eight stations, one dashed route — from the drainage where data enters the basin to the benchmark at the summit where a model stands watch. Elevation on this sheet is effort; the contour interval is yours to set. The profile below records the route as surveyed. Each station code links to its ground.

Stations of the Traverse

OBSERVED IN ORDER · PLATES I–VIII

STA-01

GRID 031-114
ELEV 120 · THE DRAINAGE

Ingest — The Drainage

Every source that feeds the traverse is charted here: CSV, Excel, JSON, Parquet, and S3-compatible storage. Data enters the basin at the drainage, is logged as a first-class source, and stays yours from the first reading.

STA-02

GRID 034-118
ELEV 220 · THE OVERLOOK

FIELD NOTE: SEGMENTATION AND CAUSAL DISCOVERY RUN FROM THE SAME OVERLOOK — NO EXTRA PERMIT REQUIRED.

EDA — The Overlook

First full view of the ground. Skyulf runs an automated exploratory survey of every dataset: statistical profiling, distributions, correlations, outliers, segmentation, causal discovery, and target analysis — plotted before you write a single transform.

STA-03

GRID 038-121
ELEV 300 · THE SWITCHBACKS

Pipeline — The Switchbacks

Node-based pipelines wired on the visual canvas: preprocessing, feature engineering, splitting, modeling. Every edge is visible, every step is yours to re-route — and any visual work exports to Jupyter notebooks, full or compact, whenever you want the trail in code form.

STA-04

GRID 041-126
ELEV 240 · THE DESCENT

FIELD NOTE: DESCENT MAY TERMINATE IN A LOCAL MINIMUM — SEE DEPRESSION A, THIS SHEET.

Train — The Descent

Training runs in the background — Celery with Redis, or background threads — while you keep surveying. Jobs queue, execute, and report back on their own clock; the descent proceeds even while the rest of the traverse moves on.

STA-05

GRID 045-131
ELEV 520 · THE SADDLE

Compare — The Saddle

Experiment comparison at the col: runs laid side by side so you can read the terrain between them before committing to a route. Two valleys open below this point; the survey picks the one with footing.

STA-06

GRID 048-134
ELEV 620 · THE CAIRNS

Registry — The Cairns

Every promoted model is staked and recorded: the model registry with audit history and diagnostics. Who moved it, when, and why — the cairns stay standing so no one walks this route blind twice.

STA-07

GRID 052-138
ELEV 740 · THE RIDGELINE

Deploy — The Ridgeline

Deployment and inference from your own ground. Self-hosted end to end — no black-box SaaS between you and the model. The ridgeline is exposed, but it is yours, and the path to it is documented on this sheet.

STA-08

GRID 055-142
ELEV 900 · THE BENCHMARK

Monitor — The Benchmark

Drift monitoring keeps watch on what you deployed. From the benchmark the whole traverse is visible — and so is any movement in the ground below. The survey does not end at the summit; it repeats. Full report at the watch station, next spread.

Two Routes to the Summit

BOTH TRAILS GRADED · EQUAL RIGHT OF WAY

Skyulf is two first-class interfaces to one lifecycle. The visual platform and the Python engine share the same ground — pick a trailhead at either end of the sheet and you arrive at the same summit. Nobody is forced onto the other's route.

ROUTE A — THE VISUAL PLATFORM

The Node Canvas

The self-hosted visual platform: datasets, pipelines, training, comparison, registry, deployment and monitoring on one canvas. Wire it visually, then export any work to Jupyter notebooks — full or compact. Nothing is trapped in the canvas.

# the whole platform, on your own ground
docker compose up -d
  • Self-host with Docker Compose
  • SQLite to start, PostgreSQL at scale
  • Local or S3-compatible storage
  • Background training via Celery + Redis

Scout the terrain first: the hosted demo at api.skyulf.com needs no signup.

ROUTE B — THE PYTHON ENGINE

skyulf-core

The independent Apache-2.0 Python package: the same engine that powers the canvas, usable directly in your own scripts and notebooks. No canvas required — and anything drawn on the canvas exports back into notebook country beside it.

# the same engine, no canvas required
pip install skyulf-core
  • Apache-2.0 licensed, on PyPI
  • Runs wherever Python runs: scripts, notebooks, jobs
  • Visual work lands beside it as exported notebooks
  • One lifecycle, one engine, two trailheads

skyulf-core on PyPI · source on GitHub

Both routes are maintained to the same grade. If your team refuses black-box SaaS, this is the trail that keeps every step on ground you own.

The Watch Station

DRIFT MONITORING · WX NOTE ATTACHED

A deployed model sits on moving ground. Upstream data shifts, distributions wander, and the slope you charted last season is not the slope underfoot today. Skyulf watches deployed models for drift and keeps the audit trail alongside — so when the terrain moves, you re-run the traverse instead of trusting an old map.

This is the station that never closes. Monitoring, diagnostics and audit history stay open on the summit for as long as the model stands.

THE GROUND MOVES — THE SURVEY REPEATS
