01 · THE PROBLEM

Leakage isn't a bug in your code.
It's a property of your workflow.

Most notebooks fit imputers, scalers and encoders on the full dataset, then split. The test set quietly teaches the preprocessing. Scores look great in the notebook — and collapse the day the model meets real data.

THE NOTEBOOK WAY

Fit first, split later

full datasetall rows
──▶
SimpleImputer.fit() on everything
──▶
train/test splittoo late
──▶
model94% 😌

The imputer's statistics already contain the test rows. The "holdout" is a fiction — and no amount of careful plotting reveals it.

THE SKYULF WAY

Split first, learn from train only

full datasetall rows
──▶
splitterstep 0, always
──▶
Learn nodesfit on train only
──▶
Apply nodestransform val/test

Fitting and transforming are different node types. The validator rejects any fit configured before the split — before a single row is processed.

Honest scores by construction. Because Learn and Apply are separate node types and validation runs before execution, a leaky pipeline can't sneak through a deadline, a copy-paste, or a teammate's canvas.

02 · THE RULE

Three guarantees, enforced by the canvas itself.

G-01

Honest scores by construction

Preprocessing can only learn from training rows. The structure of the canvas — not your discipline — keeps the test set unseen.

  • Separate Learn (fit) and Apply (transform) nodes
  • Leakage validation blocks the run before it starts
  • The exact fix is named in the error message
G-02

Reproducible by default

Every canvas gets a fingerprint, and every trained model ships with a model card — data, parameters and metrics recorded together.

  • Canvas fingerprint per run
  • Model registry with versions and artifacts
  • Export any canvas to a runnable Jupyter notebook
G-03

Operable after training

The workflow doesn't end at a good score. Live data is compared against the training baseline, and failures point at themselves.

  • Per-column drift measured four ways
  • Error log links straight to the failing node
  • Slow-node profiling and an audit trail

Move the imputer, get a green exit.

The validator doesn't just say "no". It tells you which step to move where — then gets out of the way. Fix applied, same command, one second later:

03 · THE LIFECYCLE

Seven stations.
One connected workflow.

Scroll the rail — every stage lives in the same project, so nothing gets lost between the notebook and what's actually running.

STN 01

Ingest

Point it at a file: CSV, Excel, JSON, Parquet or an S3-compatible bucket. Polars reads it, columns get profiled, and every version is kept so results stay traceable.
  • Types and quality issues detected on upload
  • Dataset versions preserved
STN 02

Explore

One click profiles every column: distributions, correlations, outliers, interactions and clusters — plus surrogate trees and causal discovery for what actually drives the target.
  • Automated EDA with statistical alerts
  • 2D/3D bivariate and PCA views
STN 03

Build

Drag nodes, connect them, branch the pipeline to try two feature strategies side by side. Per-node validation blocks bad runs and points at the fix.
  • 35 nodes: cleaning, encoding, scaling, text, time, geo
  • Branches run in parallel
STN 04

Train & tune

Runs execute as background jobs — the UI never freezes. Start with defaults, then switch on grid, random, halving or Optuna search and watch trials report in.
  • Classification, regression, clustering, text
  • Voting and stacking ensembles with nested tuning
STN 05

Compare

Every run keeps its metrics, curves and confusion matrix. Put runs side by side, see which change helped, and tune decision thresholds instead of accepting 0.5.
  • ROC, confusion matrix, per-class metrics
  • Threshold optimisation on a held-out set
STN 06

Deploy

Trained models land in a registry with versions and artifacts. Promote one to active and it serves behind a REST endpoint. Full deployment history — rollback is a decision, not archaeology.
  • Versioned registry with stored artifacts
  • REST predictions from the active version
STN 07

Monitor

Models decay because the world moves. Live data is compared against the training baseline column by column, with an error log, slow-node profiler and audit trail.
  • Drift measured four ways per column
  • Error log links to the failing node

One workflow. Visual or code — your call.

The canvas and the package are equal citizens. Build visually and export to Jupyter, or script everything with the Apache-2.0 core. Nothing is trapped in either.

A node-based workspace for the whole lifecycle — cleaning to monitoring — with validation that runs before execution, not after deployment.

  • Multi-branch pipelines run in parallel via Celery or background threads
  • One-click export to a fully runnable Jupyter notebook

The package

CODE · APACHE-2.0

skyulf-core runs the same engine in your own scripts and notebooks — no server required.

import polars as pl from skyulf import EDAAnalyzer, EDAVisualizer df = pl.read_csv("your_dataset.csv") analyzer = EDAAnalyzer(df) profile = analyzer.analyze( target_col="target", task_type="Classification", ) viz = EDAVisualizer(profile, df) viz.summary() # rich terminal dashboard viz.plot() # matplotlib charts
  • Zero-copy Arrow hand-off from Polars to scikit-learn
  • Optional extras for EDA, viz and NLP embeddings
$ pip install "skyulf-core[eda,viz]"
