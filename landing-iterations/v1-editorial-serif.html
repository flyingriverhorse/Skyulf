Point it at a file and start working

Upload CSV, Excel, JSON or Parquet, or connect an S3-compatible bucket. Skyulf reads it with Polars, profiles the columns and keeps every version you load.

Understand the data before you model it

One click profiles every column: distributions, correlations, outliers, interactions, clusters. Surrogate decision trees and causal discovery show which relationships drive the target.

Design the pipeline instead of retyping it

Drag nodes onto the canvas and connect them. Branch a pipeline to try two feature strategies side by side, preview any node's output, and let validation block a bad run early.

Train in the background, tune when it matters

Runs execute as background jobs, so long training never freezes the UI. Switch on grid, random, halving or Optuna search and watch each trial report as it finishes.

Compare runs and pick a winner on evidence

Every run keeps its metrics, curves and confusion matrix. Put runs next to each other and tune decision thresholds rather than accepting whatever 0.5 gives you.

Promote a version, serve predictions

Trained models land in a registry with versions and artifacts. Promote one to active and it is served behind a REST endpoint. Full deployment history is kept for audit.

Find out before your users do

Skyulf compares live data against the training baseline column by column and flags what shifted — with an error log, slow-node profiler and an audit trail of every change.

03

Your model says 94%. Production says 71%.

Fill missing values, scale a column or encode a category before you split into train and test, and those steps quietly learn from the test rows. Your validation score now includes answers it was supposed to be guessing. The code runs fine. The number just isn't real.

Usually nothing is broken. The score was just measured wrong, and nothing in a normal notebook tells you that. Skyulf checks the order of your pipeline and tells you in plain language — on the canvas and in the library.

Every node is split into a part that learns and a part that applies. Learning only ever sees training data, and what it learned is saved as explicit parameters, so inference can never accidentally refit on new data.

▲ validate_leakage_safety() Step 0 ('SimpleImputer') is configured before the train/test split (step 1, 'TrainTestSplitter') and will fit its statistics on the full dataset including the test set — move it after the splitter.

05

Questions people actually ask.

What is Skyulf?

Two things that share one engine: skyulf-core, a Python library giving you a single pipeline API over scikit-learn, and a self-hosted workspace where you build that same pipeline on a canvas. It covers the parts a notebook leaves to you: ordering steps so the test set stays untouched, versioning runs, comparing experiments, serving a model and watching it drift.

Do I have to self-host it?

You can try the hosted demo first. For real work you run it yourself with docker compose up, which takes a few minutes. Because it runs on your machine or server, your data never has to leave it — usable in hospitals, banks and anywhere else the data legally cannot go to a third party.

Is this really free?

Yes. skyulf-core is Apache 2.0 — use it in anything, including closed-source commercial products. The platform (backend and canvas) is AGPLv3, so improvements to the application itself are shared back.

Can I use this in production?

It is perfect for internal tools, research and experimentation. A stable v1.0 for critical production workloads is in progress.

How can I contribute?

Contributions are welcome at GitHub — code, documentation, bug reports or feature ideas.
