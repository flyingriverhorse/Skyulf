1.0 — GENERAL DESCRIPTION

Skyulf is a connected machine for the machine-learning lifecycle. Data enters at the hopper as files or remote sources — CSV, Excel, JSON, Parquet, or an S3-compatible bucket — and moves station to station through exploration, pipeline construction, training, comparison, deployment, and monitoring, without leaving the works.

The system is built for data scientists, ML engineers, developers, and product teams who refuse black-box SaaS. Two control modes are fitted as standard and carry equal authority: a self-hosted visual node-canvas console, and the independent Apache-2.0 Python package skyulf-core, operated from scripts and notebooks. Work authored on the visual line is never trapped in the canvas; it exports to standard Jupyter notebooks, full or compact, on demand.

Provisioning is operator-selected: SQLite to start, PostgreSQL at scale; artifacts on local storage or S3-compatible storage. Background training runs on Celery with Redis, or on background threads. This manual covers installation, operation, both control modes, maintenance, and specifications of the system as delivered.

SECTION 2Installation

Three installation paths are supplied. Select one at first commissioning; paths may coexist afterwards (a hosted inspection does not affect a self-hosted unit).

PROCEDURE 2.1 — PRE-OPERATION INSPECTION, HOSTED DEMO (NO SETUP)

  1. STEP 1

    Open the hosted demo console at api.skyulf.com. No signup and no installation are required.

  2. STEP 2

    Walk the stations in order — sources, EDA, canvas, jobs, registry, deployments, drift — exactly as described in Section 3.

  3. STEP 3

    To take ownership of a unit, proceed to Procedure 2.2 or 2.3.

PROCEDURE 2.2 — STANDALONE PYTHON OPERATION (skyulf-core)

  1. STEP 1

    Install the independent package from the command line:

    $ pip install skyulf-core
  2. STEP 2

    Import and operate it from scripts and notebooks. The package does not require the visual platform.

  3. STEP 3

    Source and issue tracking: github.com/flyingriverhorse/Skyulf. Distributed under Apache-2.0.

PROCEDURE 2.3 — FULL SYSTEM SELF-HOST (DOCKER COMPOSE)

  1. STEP 1

    Obtain the source:

    $ git clone https://github.com/flyingriverhorse/Skyulf
  2. STEP 2

    Raise the stack with the shipped compose file:

    $ docker compose up -d
  3. STEP 3

    Confirm background training transport: Celery with Redis for worker operation, or background threads where a broker is not wanted.

PROCEDURE 2.4 — DATABASE & STORAGE PROVISIONING

  1. STEP 1

    Start on SQLite. No external database is required at commissioning.

  2. STEP 2

    At scale, point the system at PostgreSQL; no change to operating procedure follows.

  3. STEP 3

    Select artifact storage: local filesystem or S3-compatible storage.

NOTICE

Provisioning is a choice, not a tier. SQLite to start, PostgreSQL at scale; local or S3-compatible storage. Both ends of each pair are supported as delivered.

SECTION 4Two Control Modes

One machine, two control stands. Both are first-class; neither is a wrapper for the other.

MODE A — VISUAL CONSOLE

The self-hosted node-canvas platform. The whole line of Section 3 is driven from one console:

  • Drag nodes from the palette; wire ports on the canvas.
  • Run previews and background training from the run controls.
  • Compare experiments, ledger models in the registry, dispatch deployments, serve inference.
  • Read drift, audit, and diagnostic instruments without leaving the console.
# inspect a live unit, no signup
> https://api.skyulf.com
# or commission your own
$ docker compose up -d

MODE B — skyulf-core COMMAND OPERATION

The independent Apache-2.0 Python package. The same lifecycle, operated from scripts and notebooks:

  • Install standalone; no console, no server required.
  • Drive exploration, pipelines, training, and comparison in code.
  • Compose with your own tooling — it is a package, not a platform lock.
  • Runs in notebooks today and in CI tomorrow, unchanged.

SERVICE PROCEDURE 4.3 — REMOVING THE ASSEMBLY: YOUR WORKFLOW LEAVES AS A STANDARD NOTEBOOK

  1. STEP 1

    At the visual console, call the export control for the workflow on the canvas.

  2. STEP 2

    Select the form: FULL (the complete workflow) or COMPACT.

  3. STEP 3

    The workflow leaves as a standard Jupyter notebook. It is now ordinary code artifact: version it, share it, run it anywhere notebooks run.

CAUTION

No black-box lock-in. Work authored on the visual line is never trapped in the canvas. Export any workflow as a standard Jupyter notebook — full or compact — at any time, and operate it outside Skyulf. A machine you cannot carry out of the shop is not yours.

SECTION 5Maintenance & Diagnostics

The system ships its own instruments: an error log with severities and tracebacks, slow-node runtime analysis, drift reports with per-column distance metrics, and an audit history of changes. Use them before touching the line.

FAULTPROBABLE CAUSEREMEDY
Training job halts; ledger reads Failed.Node-level failure during a pipeline run.Open the job detail; pull severity and traceback from the error log (FIG. 9-A); correct the node; re-run.
Pipeline slower than specified.One step type absorbing runtime out of proportion to its share.Open slow nodes (FIG. 9-B); rank step types by total and p95 over the window; optimize or re-split the line.
Deployed model disagrees with training-time behavior.Production data has drifted from the training reference.Run a drift report (FIG. 9-C); read per-column Wasserstein, PSI, KL divergence, and KS p-value; retrain from the registry against fresh data.
Operator cannot determine what changed.Multiple sessions edited workflows or deployments.Consult the audit history; changes are recorded; deployment history names what shipped and when.
Workflow must leave the platform.Portability requirement; external review or tooling.Execute Service Procedure 4.3; the workflow departs as a standard Jupyter notebook, full or compact.
CAUTION

Diagnose before re-running. Audit history, job diagnostics, and drift reports are fitted as standard. A re-run without a reading wastes the instrument and the hour.
