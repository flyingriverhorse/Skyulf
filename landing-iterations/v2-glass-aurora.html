// the lifecycle

Raw file in.
Monitored model out.

Point it at a file and start working

Upload CSV, Excel, JSON or Parquet, or connect an S3-compatible bucket. Skyulf reads it with Polars, profiles the columns and keeps every version you load, so you can always tell which data produced which model.

Understand the data before you model it

One click profiles every column: distributions, correlations, outliers, interactions and clusters. Surrogate decision trees and causal discovery show you which relationships actually drive your target.

Design the pipeline instead of retyping it

Drag nodes onto the canvas and connect them. Branch a pipeline to try two feature strategies side by side, preview any node's output as a table, and let validation block a run before it wastes your time.

Train in the background, tune when it matters

Runs execute as background jobs, so a long training run never freezes the UI. Start with defaults, then switch on grid, random, halving or Optuna search and watch each trial report as it finishes.

Compare runs and pick a winner on evidence

Every run keeps its metrics, curves and confusion matrix. Put runs next to each other, see which change actually helped, and tune decision thresholds rather than accepting whatever 0.5 gives you.

Promote a version, serve predictions

Trained models land in a registry with their versions and artifacts. Promote one to active and it is served behind a REST endpoint you can call from anything. The full deployment history is kept for audit.

Find out before your users do

Skyulf compares live data against the training baseline column by column and flags what shifted. There is also an error log, a slow-node profiler and an audit trail of who changed what.

// the problem nobody sees

Your model says 94%.
Production says 71%.

Fill missing values, scale a column or encode a category before you split into train and test, and those steps quietly learn from the test rows. The code runs fine. The number just isn't real.

Skyulf checks the order of your pipeline and tells you in plain language. Every node is split into a part that learns and a part that applies — learning only ever sees training data.

// faq

Before you try it.

What is Skyulf?

Two things that share one engine: skyulf-core, a Python library giving you a single pipeline API over scikit-learn, and a self-hosted workspace where you build that same pipeline on a canvas.

Do I have to self-host it?

Try the hosted demo first with nothing to install. For real work, docker compose up takes a few minutes — no account, no credit card. Your data never leaves your machine, which is what makes it usable in hospitals and banks.

Is this really free?

Yes. skyulf-core is Apache 2.0 (use it in anything, including closed-source commercial products). The platform is AGPLv3, so improvements to the application itself are shared back.

Can I use it in production?

It is perfect for internal tools, research and experimentation. A stable v1.0 for critical production workloads is in progress.

How can I contribute?

Start at GitHub. Code, docs, bug reports or feature ideas — every contribution helps shape Skyulf.
