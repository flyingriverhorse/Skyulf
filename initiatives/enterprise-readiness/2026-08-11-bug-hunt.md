# Skyulf concrete bug hunt

> **Partially promoted into [`../growth/`](../growth/2026-08-11-growth-plan.md) (2026-08-11).**
> All 9 findings were independently re-verified. Findings #2, #3, #6, #7 and
> #9 became Stage 0 (Trust Floor) items T1–T3 and T6; #1, #4, #5 and #8 went
> to the growth plan's "Verified backlog".
>
> **Three corrections from that re-verification:**
> 1. **#2/#3 understate severity and cause.** *Every* row is mislabelled and
>    `y` keeps its original length while `X` shrinks. The cause is not local
>    to the two nodes: `@apply_method` and `apply_dual_engine` each unpack
>    `(X, y)`, so composing them yields `y = None` inside the node.
> 2. **#5 and #8 overstate severity.** #5 self-heals on the next poll in
>    most paths; #8 is a hardcoded-constant mismatch with no data-loss or
>    security impact.
> 3. **#1 has an additional defect not recorded here:** `skip_locked=True`
>    (`jobs.py:113`) lets `find_active_job` silently skip a row locked by a
>    concurrent transaction, so deduplication can fail *within* a single
>    process, not only across processes.

**Date:** 2026-08-11  
**Scope:** preprocessing/calculators, execution, frontend state, time/type handling, and job concurrency.  
**Excluded:** previously reported cancellation and pipeline-version races, upload decompression bomb, SSRF findings, permission placeholder, IP-only limiting, OneHot allow-list, and ManualBounds UI gap.

## Findings

### 1. Cross-process duplicate job submission is still possible

**Severity: High**

**Location:** `backend/ml_pipeline/_internal/_routers/run_pipeline.py:41-51, 187-207`; `backend/ml_pipeline/_execution/jobs.py:104-120`; `backend/ml_pipeline/_execution/basic_training_manager.py:53-70`; `backend/database/models.py:302-331`.

```py
# run_pipeline.py
_submit_locks: dict[str, asyncio.Lock] = {}
...
existing_job_id = await JobManager.find_active_job(...)
...
job_id = await JobManager.create_job(...)
```

```py
# jobs.py
stmt = (...).with_for_update(skip_locked=True).limit(20)
rows = (await session.execute(stmt)).all()
...
return None
```

**Reproduction:** Run two Uvicorn/FastAPI workers behind a load balancer. Send two identical `/pipeline/run` requests concurrently so each lands on a different process while no active row yet exists. Each process owns a separate in-memory `_submit_locks` dictionary; each `SELECT ... FOR UPDATE` sees no row to lock; both create and enqueue a job.

**Actual:** Two training/tuning jobs run for the same dataset/node/branch, consuming duplicate resources and potentially creating duplicate registry versions/artifacts.

**Expected:** Exactly one active job should be created for the idempotency key. A database-enforced unique/idempotency claim is needed; a process-local lock cannot provide this.

### 2. Lag Features sorts/drops `X` but returns the original `y`

**Severity: High**

**Location:** `skyulf-core/skyulf/preprocessing/time_series/lag.py:45-51, 67-73`.

```py
X_out = X.sort(sort_by) if sort_by and sort_by in X.columns else X
...
if params.get("drop_na"):
    X_out = X_out.drop_nulls()
return X_out, _y
```

```py
df = sort_pandas(X.copy(), params.get("sort_by"))
...
if params.get("drop_na"):
    df = df.dropna()
return df, _y
```

**Reproduction:** Call the pandas applier with:

```py
X = pd.DataFrame({"t": [2, 1, 3], "x": [20, 10, 30]})
y = pd.Series(["row-t2", "row-t1", "row-t3"])
_apply_pandas(X, y, {"columns": ["x"], "lags": [1], "sort_by": "t", "drop_na": True})
```

This produces `X` rows for original indices `0, 2` (times 2 and 3), while `y` still has all three original rows in original order.

**Actual:** Feature rows and labels are different lengths and/or associated with the wrong observations. Downstream training can fail or train against corrupted labels.

**Expected:** Sorting must reorder `y` identically and `drop_na` must apply the same retained-row mask to `y`.

### 3. Rolling Aggregate sorts `X` while leaving target labels in their old order

**Severity: High**

**Location:** `skyulf-core/skyulf/preprocessing/time_series/rolling.py:63-74, 111-115`.

```py
X_out = X.sort(sort_by) if sort_by and sort_by in X.columns else X
...
return X_out, _y
```

```py
df = sort_pandas(X.copy(), params.get("sort_by"))
...
return df, _y
```

**Reproduction:** Use the same shuffled `X`/`y` as finding 2, but run:

```py
_apply_pandas(
    X, y,
    {"columns": ["x"], "aggregations": ["mean"], "sort_by": "t"},
)
```

The output feature order is time `1, 2, 3`, but labels remain `row-t2, row-t1, row-t3`.

**Actual:** Every sorted row can be trained/evaluated against another row's target.

**Expected:** The target must be reordered together with the frame. This applies to both pandas and Polars paths.

### 4. The canvas permits cyclic pipelines and executes them in invalid order

**Severity: Medium**

**Location:** `frontend/ml-canvas/src/core/store/useGraphStore.ts:289-453`; `frontend/ml-canvas/src/core/utils/pipelineConverter.ts:165-188, 586-588`; `backend/ml_pipeline/_execution/engine/__init__.py:123-146, 333-339`.

```ts
// useGraphStore.ts
set({
  edges: addEdge(connection, get().edges),
});
```

```ts
// pipelineConverter.ts
while (queue.length > 0) {
  const nodeId = queue.shift();
  ...
  outgoingEdges.forEach(e => queue.push(e.target));
}
```

```py
# engine/__init__.py
for node in config.nodes:
    node_result = self._execute_node(node, job_id=job_id)
...
return self.artifact_store.load(input_node_id)
```

**Reproduction:** On the canvas create `Dataset -> A -> B`, then connect `B -> A`. `onConnect` has no reachability/cycle check. The converter's visited-set BFS emits a best-effort order rather than rejecting the graph; the engine then tries to load an upstream artifact that has not been produced.

**Actual:** The user gets a late, implementation-level artifact-not-found failure (or other execution-order failure), after submitting a graph that should have been rejected.

**Expected:** The connection must be blocked or graph validation must return a direct cycle error before preview/job creation.

### 5. Out-of-order job-list responses can revert newer job state

**Severity: Medium**

**Location:** `frontend/ml-canvas/src/core/store/useJobStore.ts:82-98, 145-153`.

```ts
const latestJobs = await jobsApi.getJobs(PAGE_SIZE, 0);

set(state => {
  if (state.jobs.length <= PAGE_SIZE) {
    return { jobs: latestJobs };
  }
  return { jobs: [...latestJobs, ...state.jobs.slice(PAGE_SIZE)] };
});
```

```ts
const jobs = await jobsApi.getJobs(PAGE_SIZE, 0);
set({ jobs, isLoading: false, hasMore: jobs.length === PAGE_SIZE });
```

**Reproduction:** Start polling request A, delay its response so it contains `job-1: running`; allow request B (a WebSocket-triggered refresh or a manual `fetchJobs`) to finish first with `job-1: completed`; then resolve A.

**Actual:** A applies after B and overwrites the completed state with `running`. There is no request sequence, abort, or freshness check.

**Expected:** Only the newest request for the same list scope may update the Zustand store.

### 6. Feature Selection's advertised default is an unknown method and silently does nothing

**Severity: Medium**

**Location:** `skyulf-core/skyulf/preprocessing/feature_selection/facade.py:44-55, 66-77`.

```py
_FS_CALCULATORS = {
    "variance_threshold": VarianceThresholdCalculator,
    ...
}
...
params={"method": "variance", "threshold": 0.0},
...
method = config.get("method", "select_k_best")
ctor = _FS_CALCULATORS.get(method)
if ctor is None:
    logger.warning(f"Unknown feature selection method: {method}")
    return {}
```

**Reproduction:**

```py
X = pd.DataFrame({"constant": [1, 1, 1], "variable": [1, 2, 3]})
artifact = FeatureSelectionCalculator().fit(
    X, {"method": "variance", "threshold": 0.0}
)
# artifact == {}; applying it retains "constant"
```

**Actual:** A configuration matching the node metadata's default logs `Unknown feature selection method: variance`, returns an empty artifact, and leaves constant columns in the dataset.

**Expected:** The default must be `variance_threshold`, or `variance` must be an alias. The warning is also a concrete misleading user-facing node warning: it calls the component's own default “unknown.”

### 9. FeatureMath silently drops datetime extraction for mixed-offset timestamps

**Severity: Medium**

**Location:** `skyulf-core/skyulf/preprocessing/feature_generation/_pandas_ops.py:173-186, 214-241`.

```py
dt = pd.to_datetime(df_out[col], errors="coerce")
...
df_out[f"{col}_{feat}"] = builder(dt)
...
except Exception as e:
    logger.warning(f"Failed to extract datetime features for column {col}: {e}")
```

```py
if op_type == "datetime_extract":
    _pandas_datetime_apply(op, df_out)
    continue
```

**Reproduction:**

```py
X = pd.DataFrame({
    "when": [
        "2024-01-01T00:00:00+00:00",
        "2024-01-01T00:00:00+01:00",
    ]
})
_featgen_apply_pandas(X, None, {
    "operations": [{
        "operation_type": "datetime_extract",
        "input_columns": ["when"],
        "datetime_features": ["hour"],
    }]
})
```

On current pandas this parses to an object series (with a FutureWarning); `.dt` raises, the catch logs a warning, and the method returns success without `when_hour`.

**Actual:** A valid timestamp column yields a successful pipeline/node with the requested feature absent. The warning says only “Can only use .dt accessor with datetimelike values,” concealing the actionable mixed-timezone cause.

**Expected:** Normalize to UTC (`utc=True`) or report a failed, actionable validation error; do not silently return a successful no-op.
