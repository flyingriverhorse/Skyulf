## Test corrections and the meaningful failed gate

The test setup initially assigned automatic promotion to the shared multi-model
workflow. Components must retain manual promotion while the set owns automatic
release; Core preflight caught this before that scenario trained.

The first generated-layout run attempted explicit reject while still in automatic
mode. Existing validation correctly requires `manual_approval` for these single-
model operator actions. The harness now changes policy before invoking reject.
The next assertion used `DESCRIBE HISTORY` on a full-rebuild logical view; it was
corrected to inspect the physical `_v1` generation. Neither required a product fix.

The first set's one-trial test budget selected an underfitting risk model:
heldout accuracy was **0.458333**, below the unchanged **0.50** threshold. Revenue
and cost passed, but the complete set correctly remained challenger v1 with no
champion. The durable quality decision identifies only `risk` as failing.

To test the successful path, only the risk declaration was customized to grid
search `C=[1.0, 10.0]` (two candidates). Sibling model settings and all quality
thresholds were retained. The resulting set passed and became champion v2.
This is an acceptance-fixture adjustment, not a change to shipped search defaults
or weakened quality gates. The failed first set and its evidence were preserved.
