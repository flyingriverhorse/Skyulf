Drift & monitoring

Find out from the system, not from the business.

Drift monitoring measures live data against the distribution the model was trained on, and reports it inside the project that trained it. The lineage is already there — the dataset, the EDA, the pipeline graph, the run, the registered version. You are not reconstructing history under pressure.

Registry & serving

Versions with history, not folders with dates.

Promote a run into the registry, keep its version history, deploy it, and send inference through it, all inside the same self-hosted stack. Artifacts sit on local disk or in your own S3-compatible storage. Metadata starts on SQLite and moves to PostgreSQL when the deployment grows.

  • StorageLocal disk or S3-compatible object storage. Your bucket, your credentials
  • MetadataSQLite for small deployments, PostgreSQL for larger ones
  • ExecutionCelery with Redis, or background threads
  • LicencePlatform AGPL-3.0 · skyulf-core Apache-2.0

Upstream

All of that only holds because the upstream is in the same system.

Ingest CSV, Excel, JSON, Parquet, or S3-compatible storage. Run automated EDA covering distributions, correlations, outliers, segmentation, target analysis, causal discovery. Build preprocessing, feature engineering, splitting, and modeling as a node graph where the order of operations is visible, which is where leakage usually hides.

Then compare the runs instead of trying to remember them.

And none of it locks the work inside a canvas.

The same engine ships as skyulf-core under Apache-2.0, a Polars-friendly pipeline layer built on scikit-learn rather than replacing it. Use the platform, use the package, or move between them. Any canvas exports to a Jupyter notebook.

Run it without the platform

Preprocessing, classification, regression, clustering, text models, tuning, evaluation, and optional SHAP explanations behind one composable API.

  • Python 3.12+, install from PyPI
  • Save and load a fitted pipeline as one artifact
  • Optional extras for tuning, explainability, NLP, geo
  • Apache-2.0
View on PyPI Documentation 
$ pip install skyulf-core

import polars as pl
from skyulf import SkyulfPipeline

customers = pl.read_csv("customers.csv")

pipeline = SkyulfPipeline({
    "preprocessing": [
        {"name": "split",
         "transformer": "TrainTestSplitter",
         "params": {"target_column": "purchased",
                    "test_size": 0.2, "random_state": 42}},
        {"name": "impute_income",
         "transformer": "SimpleImputer",
         "params": {"columns": ["income"],
                    "strategy": "median"}},
        {"name": "encode_city",
         "transformer": "OneHotEncoder",
         "params": {"columns": ["city"],
                    "handle_unknown": "ignore"}},
    ],
    "modeling": {"type": "logistic_regression",
                 "params": {"max_iter": 500}},
})

pipeline.fit(customers, target_column="purchased")
pipeline.save("customer_model.pkl")
