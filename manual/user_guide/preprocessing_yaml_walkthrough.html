    Build preprocessing with YAML

    Configure a generated Databricks project's preprocessing by editing YAML. This walkthrough uses built-in steps: the shipped src/features/ Python files can stay unchanged. It covers fixed eligibility, missing values, categorical encoding, scaling, outlier exclusion and saved prediction. The examples use the preprocessing additions in Skyulf Core 0.9.4.

    Use the preprocessing catalog for every step's parameter types, defaults, allowed values and output contract. The complete list below links all registered names, including operations that require custom Python or standalone use.

    1. Start from a generated project

    Generate a single-model classification project using the Bundle setup guide. Keep its source table, record keys, registry, training split and deployment settings. This walkthrough replaces two complete recipe files and updates selected fields in config/training.yml. It does not create a Delta table or deploy an endpoint by itself.

    File What belongs here When it runs
    config/pre_split.yml Fixed input normalization and eligibility, such as an age range. Before splitting training data; the generated scoring policy reuses feature-only rules.
    config/preprocessing.yml Imputation, learned category maps, scaling, feature selection and learned outlier detection. Fitted on training rows; fitted again inside training folds when cross-validation fits a fold. Saved state is replayed at prediction.
    config/training.yml Input columns, target, model and the names of the two selected recipes. Selects what a training run builds.

    A recipe is an ordered list of steps. Only the named recipe runs. default: [] and none: [] below deliberately do nothing; defining four recipes does not combine them. Each built-in step has a unique name, a case-sensitive transformer and its params mapping.

    2. Apply fixed rules before the split

    Replace config/pre_split.yml with this complete file:

    version: 1
recipes:
  default: []
  none: []
  eligible:
    - name: income_marker
      transformer: ValueReplacement
      params: {columns: [income], to_replace: -200, value: null}
    - name: age_range
      transformer: ManualBounds
      params: {bounds: {age: {lower: 0, upper: 120}}}

    The marker -200 becomes a missing measurement; it is not included in the mean learned later. The fixed age rule removes row 32 before the training split. Bounds are inclusive. ManualBounds retains missing values; use an explicit missing-value rule if a missing age should be ineligible rather than imputed.

    Both rules read features only. The generated mode: pre_split policy in config/scoring.yml can reuse them without editing Python or enabling a target-skip switch. At scoring time an out-of-range age keeps its result row with scoring_status=excluded, an empty prediction and exclusion_reason=pre_split:age_range.

    Pre-split accepts a restricted set of fixed operations: DropMissingRows, ManualBounds, Deduplicate, ValueReplacement, TextCleaning, AliasReplacement, InvalidValueReplacement and Casting. Each has additional pre-split constraints. Learned means, quantiles and outlier boundaries belong in preprocessing, not before the split. If a rule reads the target, follow the explicit target-filter policy instead of copying the feature-only policy in this example.

    3. Define alternative fitted recipes

    Replace config/preprocessing.yml with this complete file. The recipes share the same raw input columns, so switch between them by changing one recipe name in training configuration.

    version: 1
recipes:
  default: []
  none: []
  customer:
    - name: fill_numeric
      transformer: SimpleImputer
      params: {columns: [age, income, tenure], strategy: mean}
    - name: rare_segments
      transformer: RareCategoryGrouping
      params: {columns: [segment], min_count: 3, replacement: Other}
    - name: segment_frequency
      transformer: FrequencyEncoder
      params: {columns: [segment], mode: frequency}
    - name: numeric_quantiles
      transformer: QuantileTransformer
      params:
        columns: [age, income, tenure]
        n_quantiles: 16
        output_distribution: uniform
        subsample: null
        random_state: 42
    - name: numeric_row_norm
      transformer: Normalizer
      params: {columns: [age, income, tenure], norm: l2}
  fixed_categories:
    - name: fill_numeric
      transformer: SimpleImputer
      params: {columns: [age, income, tenure], strategy: mean}
    - name: scale_measurements
      transformer: StandardScaler
      params:
        columns_regex: '^(age|income|tenure)$'
        dtype: numeric
        exclude_columns: [customer_id]
    - name: fixed_segments
      transformer: OneHotEncoder
      params:
        columns: [segment]
        categories: {segment: [A, B, C]}
        column_names: slug
        max_categories: null
        include_missing: false
        handle_unknown: ignore
  isolation:
    - name: fill_numeric
      transformer: SimpleImputer
      params: {columns: [age, income, tenure], strategy: mean}
    - name: unusual_measurements
      transformer: IsolationForest
      params:
        columns: [age, income, tenure]
        contamination: 0.1
        n_estimators: 40
        random_state: 42
    - name: segment_frequency
      transformer: FrequencyEncoder
      params: {columns: [segment], mode: frequency}
  local_density:
    - name: fill_numeric
      transformer: SimpleImputer
      params: {columns: [age, income, tenure], strategy: mean}
    - name: scale_measurements
      transformer: StandardScaler
      params: {columns: [age, income, tenure]}
    - name: unusual_measurements
      transformer: LocalOutlierFactor
      params: {columns: [age, income, tenure], n_neighbors: 5, contamination: 0.1}
    - name: segment_frequency
      transformer: FrequencyEncoder
      params: {columns: [segment], mode: frequency}

    Choose the recipe for the behavior you need; these are alternatives, not an instruction to stack every available transform:

    Recipe What happens What the saved model remembers
    customer Impute numeric inputs, group rare segments, encode group frequency, transform each numeric column by its quantiles, then normalize each row's numeric vector. Training means, frequent-category membership, group frequencies and quantile maps; the selected columns and normalization rule.
    fixed_categories Impute and standardize numeric measurements; emit exactly segment_a, segment_b, segment_c. Numeric means/scales and the explicit vocabulary/order, including levels absent from training.
    isolation Impute, exclude rows outside the learned IsolationForest boundary, and frequency-encode segment for surviving training rows. The fitted detector and downstream category map.
    local_density Impute, scale numeric distances, exclude rows using the fitted LocalOutlierFactor detector, then encode segment. Numeric scales, the novelty detector and downstream category map.

    Quantile transformation changes each column's distribution. L2 normalization then makes each nonzero selected row vector have length one; it does not standardize columns. They are shown together to demonstrate both operations. For a random forest neither is automatically necessary; compare validation results before retaining extra steps.

    Rare grouping sends an unseen segment to Other. The next frequency encoder uses the saved frequency of that group, or zero if no such group was learned. Frequency encoding alone sends an unseen category to zero. Neither recomputes frequencies from the scoring request.

    Fixed one-hot requires explicit string vocabularies, max_categories: null and include_missing: false. Here NEW or a null segment produces three zeros; changing handle_unknown to error rejects them instead. column_names: slug normalizes output names; conflicting normalized names are rejected at fit.

    Outlier filtering changes the training population. At prediction, the scoring workflow preserves an outlier's row and reports exclusion_reason=outlier:unusual_measurements. The first exclusion reason wins: an age already rejected by the fixed rule keeps pre_split:age_range. contamination: 0.1 controls the fitted cutoff; it does not promise that exactly 10% of future requests will be excluded. Review the exclusion counts as well as the model metric before choosing a detector.

    4. Select and inspect the recipe

    Merge this fragment into the generated config/training.yml. Keep its table, record keys, registry, split, resource and quality settings. Select a classification quality metric and remove an existing tuning block if you want only the fixed model below. Use the generated model key if it differs from main.

    version: 1
defaults:
  task: classification
  input_columns: [age, income, tenure, segment]
  target_column: churn
  pre_split_recipe: eligible
  preprocessing_recipe: customer
models:
  main:
    model:
      type: random_forest_classifier
      params: {n_estimators: 40, max_depth: 6, n_jobs: 1, random_state: 42}

    Change preprocessing_recipe to fixed_categories, isolation or local_density to train that alternative. A model entry can override the defaults. Competition candidates can use different preprocessing recipes while sharing pre-split eligibility and holdout membership; independent-target models can select their own recipes. Follow the generated layout for your project type.

    Run from the generated project directory:

    python src/tools/smoke.py
python src/tools/preview.py --action train
python src/tools/preview.py --action score
python src/tools/preview.py --list-preprocessors

    Preview resolves the configuration without training the model. Inspect the selected recipes and input columns, then use your project's generated training and scoring commands. The registry listing shows metadata defaults; the parameter cards below explain the full accepted configuration. Successful preview does not prove that a particular input dataset or serving configuration will be admitted.

    Select columns once, at fit

    The fixed_categories scaler demonstrates three shared selector options:

    Option Effect in the example
    columns_regex: '^(age\|income\|tenure)$' Select these exact names; matching uses a regular-expression search, so anchors matter.
    dtype: numeric Require numeric feature columns as well as a matching name.
    exclude_columns: [customer_id] Keep identifiers out even if a broader pattern is used later. The key is already outside model inputs here.

    The rules combine with AND and resolve once from training features. Saved prediction uses the resulting explicit names. An empty selection raises an error. These rules apply to preprocessing steps that accept columns; they do not apply to pre-split rules or directly to Calculator calls. Native Spark training uses explicit names. The Canvas uses its explicit column picker. See the selection contract for dtype details and the interaction with an explicit columns list.

    5. Check saved prediction behavior

    Send raw model inputs in their recorded types; do not manually reproduce the mean, scale or category columns in a client. For example:

    customer_id,age,income,tenure,segment
101,40,3000,3,A
102,40,,3,NEW
103,150,3000,3,A
104,40,10000000,5000,B
105,40,-200,3,A

    The source record key associates each result with its input; it is not a model feature. With customer or fixed_categories, rows 101, 102, 104 and 105 are predicted, while 103 is excluded by the age rule. Missing income and the marker are imputed using the training mean. The two detector recipes can also exclude 104 for its extreme measurements. Their learned boundaries, and therefore other accepted rows, depend on the training split.

    The published scoring table keeps excluded rows, their status and reason, with null predictions. This is different from asking a bare preprocessing applier to remove rows. Use the complete saved scoring workflow for that contract. See scoring and incremental inputs for output columns.

    Training saves fitted transformations and the selected project rules with the model. Editing YAML affects the next training run; it does not change an existing registered version. Load and replay the saved artifact to check the behavior you intend to deploy.

    Execution path What must be checked
    pandas / Polars The selected configuration, input dtypes, missing values and saved replay on the chosen native engine.
    Spark worker scoring Admission of the fitted artifact for independent batches, its input/output schema and worker dependencies. This is not distributed training of the estimator.
    Serving endpoint Admission of the complete serving workflow, its raw input contract, saved rules and dependencies. A working local pipeline alone does not establish endpoint support.
    Lag or rolling features Ordered history must be supplied through the supported context workflow. A model does not fetch prior customer records by itself.

    The recipes use saved state plus individual request rows during prediction. In contrast, history-dependent operations require additional observations. Use preprocessing diagnostics and the Spark guide for artifact-specific checks. Do not infer support for every configuration from the existence of a registry entry.

    New nodes and additions to existing nodes

    The six new registered operations are FrequencyEncoder, RareCategoryGrouping, QuantileTransformer, Normalizer, IsolationForest and LocalOutlierFactor. In the Canvas they are choices within the existing Encoding, Scaling and Outlier panels, not six separate palette cards.

    Other additions are parameters or operations within existing nodes:

    Existing operation Addition and where to read the complete configuration
    OneHotEncoder Fixed string vocabularies and slug output names.
    GroupImputer Multiple group keys and hierarchical fallback. An unknown full key can fall back to a shorter key, then the saved global statistic.
    FeatureGeneration Group deviation subtracts a saved group reference from a value.
    DateFeatures Local timezone and cyclic date features, such as month sine/cosine.
    count_vectorizer / tfidf_vectorizer Per-column vocabularies separate text fields instead of joining them.
    Winsorize Per-column percentile bounds.
    ModelBasedSelection RFECV and sequential feature selection, with their own CV and feature-count controls.
    TargetEncoder Cross-fitting fold count, shuffle and seed. Training encodings remain separate from full-training maps used for prediction.
    MinMaxScaler / RobustScaler Clipping and unit-variance adjustment.
    Steps accepting columns Pattern, dtype and exclusion selectors in Core pipelines and YAML.

    Find every step and its parameters

    Each linked family contains per-step parameter tables with type, default, allowed values, effect, minimal YAML and saved-state behavior. There are 73 registered names and 69 distinct implementations, including four aliases. The following inventory includes standalone and custom-only operations; registration is not a promise that every name can be pasted into a Bundle recipe.

    Bounds and outliers ClipValues, EllipticEnvelope, IQR, IsolationForest, LocalOutlierFactor, ManualBounds, Winsorize, ZScore

    Most cards show list fragments: paste them under a named recipe in the correct phase file. ColumnFunction, FittedFunction and RowFilterFunction need a captured Python factory because YAML cannot supply a callable. Split nodes are standalone Core operations; let the Bundle own its train/holdout split. Sampling is training-only, while profile/snapshot nodes are diagnostics. Optional text, geospatial and sampling packages must be installed where the model runs. Each card states these restrictions; use the registry index to jump directly to an individual operation.
