## v0.7.5

### 🐛 Bug Fixes
- Branches that independently produce an **identical** column no longer count as a merge conflict. Two MissingIndicator branches emitting the same `*_missing` flags each "changed" the column relative to the shared ancestor, so a Feature-Target Split downstream reported a winner and offered a Merge Strategy even though nothing was discarded. `_modifiers_agree` now collapses agreeing branches to a single owner (`backend/ml_pipeline/_execution/engine/_merge.py`).
- The fan-in `window.confirm` shown when wiring a second input still described the old "column union with LAST-WINS on overlap" contract. It now explains that each column keeps the value of whichever branch changed it, and that only a genuine same-column conflict is resolved by the merge strategy (`core/store/useGraphStore.ts`).
- The Merge Strategy control now names the node it applies to and both contesting branches, and its options read `Keep <BranchName>` instead of the opaque `Last wins` / `First wins` (`PropertiesPanel.tsx`).
- The Merge Strategy control is now discoverable while wiring, not only after a run: `predictMergeConflict` compares the columns each parallel branch is configured to rewrite (excluding work done before the branches split) and surfaces the control marked `Predicted`. A run's engine advisory, which diffs real values, supersedes the prediction (`core/utils/predictMergeConflict.ts`).
### 🎨 Frontend
### 🎨 Frontend
- `NotificationCenter` nested the Dismiss `<button>` inside the row `<button>` — invalid HTML that made click and focus behavior unpredictable and misreported the row to screen readers. Split into sibling controls; also moved `markAllRead()` out of the `setOpen` updater, where it was a side effect in the render phase (FND-007).
- EDA dataset dropdown disambiguates datasets that share a name with a stable id suffix, so duplicate-text options are no longer indistinguishable (DAT-008, `core/utils/edaDatasetOptions.ts`).
- Column-wise fan-in merges now resolve **per-column ownership** instead of applying a blanket last-wins on every shared column name. The engine diffs each branch against the nearest shared ancestor: a column changed by only one branch keeps that branch's value regardless of edge order, so parallel branches editing *different* columns no longer overwrite each other. The merge strategy — and the advisory banner and "WINS MERGE" edge label — now apply only to columns two or more branches actually modified (`backend/ml_pipeline/_execution/engine/_merge.py`).
- The Merge Strategy dropdown is hidden until a run detects a genuine column conflict on that node, and its copy names the contested columns. Previously it was offered on every multi-input node, implying a winner even when the branches did unrelated work (`PropertiesPanel.tsx`, `CanvasLegend.tsx`).
- `MergeStrategy` narrowed to `'last_wins' | 'first_wins'`; the union previously advertised a `'concat'` value the engine rejects (`core/types/nodeData.ts`).
- Fan-in merges applied inputs in `nodes`-array order while the advisory banner named the last edge in `inputs` as the last-wins winner. Two unrelated orderings meant moving a node on the canvas could silently discard the branch the banner claimed had won — e.g. a log1p Transformation vanishing from the trained model. `_resolve_all_inputs` and the advisory now share one `_merge_input_order` helper that keeps the user's edge order and only reorders to put an ancestor before its own descendant (`backend/ml_pipeline/_execution/engine/__init__.py`, `_merge.py`).
- Removed the misleading `_topo_order` map: it was the index in the `nodes` array, not a topological sort, and was the source of the ordering bug above (`backend/ml_pipeline/_execution/engine/__init__.py`).
- `upstream_drop_reapplied` advisories now carry `inputs`, so the Results banner stops rendering them through the fan-in template as "merges 0 parallel branches: . No column overlap — all columns from all branches are kept" — copy that claimed nothing was dropped while columns were in fact dropped (`_merge.py`, `MergeWarningsBanner.tsx`).
- Over-limit uploads return 413 instead of `PermissionError` on Windows. Last failing backend test fixed (1072 passed).
- Drop Columns node authoritative for whole subgraph (fan-in no longer restores dropped columns).
- Deployed artifacts record upstream dropped columns.

### 🔧 Backend
- Deployment input schemas report real column types (integer/float/boolean/text/category/datetime/duration).

### 🎨 Frontend
- Preview Results panel restructured into `Data` / `Issues` / `Steps` panes with a maximize toggle. Validation banners, merge advisories, and applied-step pills previously stacked above the table and squeezed it out of the fixed 384px panel; each now owns a pane, the header carries an issue-count badge, and the table gets the full height (`ResultsPanel.tsx`).
- Inference page rebuilt as scrolling responsive shell. Form semantics across Canvas/Data/EDA/Inference.
- `FormField` primitive. Metric direction explicit across run comparison. Branch-comparison heuristic consolidated.
- Missing metric values state why. Responsive app shell + navigation down to 390px.
- Canvas click-to-add no longer overlaps. Container-aware toolbar. Accessible Add Source form.
- `RecordLink` operational-context primitive (35 tests). Reachable Data/EDA controls at narrow widths.
- Experiments discloses hidden selected runs. Evaluation tabs target renderable runs.
- EDA deep-link fixes (wrong dataset, display mismatch, silent failures).
- Canvas freeze during drag fix. Inference schema violation blocking. Jobs table duplicate rows fix.
- Shared async-state live regions (`LoadingState`/`EmptyState`/`ErrorState`); removed the duplicate toast announcement `<Toaster>` already provides. Shared `useModalFocus` focus contract across all overlays.
- Canvas validation is now an actionable loop: `validateGraph` returns structured per-node issues (configuration/connection/leakage) instead of `console.warn`ing a boolean, Run Preview and Run All block on them, and Results renders a selectable issue list that selects the offending node and opens its Properties panel. A failed run's error stays inspectable after the toast disappears. Only the issue count is announced — the list recomputes on every graph edit, so a live region around it would re-read every issue on each keystroke.
- Dataset preview no longer renders unavailable metadata as `0`, and surfaces the backend's real error message (e.g. `Invalid file path`) instead of a generic string. Sample and profile failures are reported independently, and Retry refreshes both while preserving the selected tab.
- Ingestion Jobs separates active ingestions from completed history rather than presenting every dataset ever created as a running job. Failure text now also appears on the Data Sources row (previously only the modal had it), failed sources get a Retry route, and the icon-only Cancel button got an `aria-label`.
- Threshold mutations (save/enable/disable/clear) expose scoped pending state, cannot be double-submitted, and offer an in-place retry on failure. Saved thresholds now display their provenance — metric, split, and computed-at — and a job-scoped fetch prevents one job's thresholds being attributed to another.
