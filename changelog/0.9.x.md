# Changelog — 0.9.x Series

For the version index, see root [CHANGELOG.md](../CHANGELOG.md).

## v0.9.0 — Unreleased

Target: optional Spark execution and MLflow integration for Skyulf Core.
Development version: 0.9.0. This release has not been published; Spark node
execution, MLflow registry and Databricks delivery remain under development.

### Added

- Spark/MLflow initiative: architecture, implementation plans, validation gates
  and an ordered [task queue](../initiatives/spark_and_mlflow/OPEN_QUEUE.md).
  Historical readiness reports are grouped with the initiative.
- Experimental Spark test foundation (SM-00): optional `spark` extra, separate
  `requirements-spark.txt`, a Java 17/Python 3.12 CI lane and real JVM/Arrow
  worker smoke tests. The dedicated lane fails if PySpark is missing; normal
  core tests can skip the optional runtime. No Spark node capability is enabled.
- [Spark development guide](../docs/user_guide/spark.md) with isolated setup,
  a runtime example, troubleshooting and explicit support boundaries.
- Immutable execution options and row-key declarations, plus explicit
  per-node fit/apply capability checks. Unsupported engine/configuration requests
  produce structured errors without executing a node. Existing local pipelines
  remain unchanged; these contracts do not enable Spark nodes yet.

- Optional Spark engine adapter with real dataframe detection and a separate
  distributed metadata/projection protocol. Local conversion and sklearn
  entry points reject Spark inputs without collecting data. Sessions remain
  caller-owned; base imports require neither PySpark nor MLflow. This adds no
  native FE node or model inference capability yet.

- Opt-in keyed Spark `FeatureEngineer` entry point: validates schema and composite
  keys, excludes keys/target from feature selection, checks all node capabilities
  before execution, and verifies key/target preservation after native steps.
  Spark dispatcher preparation preserves distributed frames; local FE behavior
  remains available. Unknown distributed metrics replace local profiling guesses.
  Node support is enabled separately by native implementations.

- Versioned portable-state codec for StandardScaler and mean/constant
  SimpleImputer artifacts. Tagged UTF-8 JSON preserves scalar types, non-finite
  values and column order, with explicit byte limits, structural validation and
  a semantic checksum. Arbitrary Python objects are rejected; existing pipeline
  persistence and fingerprint behavior remain unchanged.

- Native Spark SimpleImputer mean/constant fit and apply: one aggregate result
  holds learned values and missing counts; apply uses Spark expressions without
  pandas conversion or Python UDFs. Portable state supports cross-engine apply
  with pandas/Polars. The keyed runner normalizes defaults, preserves explicit
  empty selections and enforces configured state-byte limits. Median/mode remain
  unsupported; the Spark guide includes pipeline and cross-engine examples.

- Native Spark StandardScaler with population variance, all four centering/scaling
  options and portable pandas/Polars/Spark state. Two bounded aggregate results
  compute statistics relative to a numeric reference to avoid large-offset mean
  errors; apply uses native Spark expressions. Null/NaN, constant/near-constant,
  empty and single-row inputs have explicit tested behavior. Numeric selection
  and name validation are shared with the native imputer.

- Portable `FeatureEngineer.export_state()` / `from_state()` for ordered imputer
  and StandardScaler chains. Versioned JSON freezes learned column selection,
  validates the total byte budget and rebinds caller-supplied Spark keys/runtime.
  Full-chain tests cover all nine pandas/Polars/Spark fit/apply combinations,
  persistence, repartitioning and bounded driver collection. A runnable Spark
  example and guide demonstrate saving and loading the fitted chain. Successful
  tuned pipelines can export their supported FE; failed model fits invalidate it.

- Standalone inference bundles with explicit `raw`/`features` inputs, frozen
  FE/model payloads, ordered input/output schemas, runtime requirements and
  corruption/budget checks. Local pandas/Polars regression and classification
  preserve probability class order and default versus opt-in threshold behavior.
  Successful pipeline fits capture schema metadata without retaining input frames;
  legacy artifacts without schemas require refitting. Includes a runnable example
  and [bundle guide](../docs/user_guide/inference_bundles.md). Trusted sklearn
  pickle payloads remain distinct from portable FE JSON and legacy persistence.

- Distributed regression inference through `predict_spark(mode="native_features")`:
  saved FE runs as native Spark expressions, then the fitted Python estimator runs
  in worker batches. Explicit row keys preserve result identity; schema/order and
  package checks precede submission. Model loading is reused within each iterator,
  and unused input columns do not reach workers. The bundle guide includes a Spark
  example and explains compatibility with existing pipeline/backend artifacts.
- Distributed classification inference through both `native_features` and
  `python_pipeline`: string binary and integer multiclass labels retain their
  manifest class order, probability columns use explicit Spark output types, and
  saved tuning/pipeline thresholds match local decisions. Partitioning and Arrow
  batch changes are covered by action-based parity tests; iterator model loading
  is bounded and incompatible worker dependencies fail before unpickling. The
  runnable `spark_batch_inference.py` example exercises both modes.
- [Illustrated inference guide](../docs/user_guide/inference_flow.md) covering
  fitted FE/model reuse, a numerical local/Spark example, and available inference
  paths. Includes four SVG diagrams and editable Mermaid sources.
- Optional MLflow tracking through `TrackingConfig` and `track_run`, with a
  dependency-free disabled mode, explicit client-bound run IDs, FINISHED/FAILED
  lifecycle, `raise`/`warn` failure policy, and opt-in config artifact digest.
  Install it with `skyulf-core[mlflow]` or `requirements-mlflow.txt`.
- Optional MLflow `pyfunc` packaging for trusted inference bundles. Explicit
  run IDs and client-bound artifact upload preserve run isolation; raw/features
  prediction parity, class/threshold metadata, named signatures, synthetic
  input examples, and clean wheel/subprocess loading are covered. Registry,
  Unity Catalog, Spark UDF and endpoint delivery remain separate gates.

### Planned scope — not yet available

- Further native Spark nodes and broader portable-state coverage.
- Worker wheel packaging and scale/RSS validation for production Spark clusters.
- Unity Catalog model resolution and registry adapters.
- Scheduled batch inference with reproducible model versions and Delta outputs.

Endpoint integrations and template/Databricks Bundle generation follow the
core and batch validation gates. Planned items are not shipped functionality;
verified delivery notes will be added as the tasks are completed.
