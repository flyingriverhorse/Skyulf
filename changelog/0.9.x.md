# Changelog — 0.9.x Series


For the version index, see root [CHANGELOG.md](../CHANGELOG.md).

## v0.9.4

- Reject invalid serving-monitor enrollment batches before acquiring the shared
  reference lock, so configuration errors cannot write a lock record or be
  hidden by an unavailable monitoring store. Valid enrollments remain guarded.
- Add FrequencyEncoder, RareCategoryGrouping, QuantileTransformer, Normalizer,
  IsolationForest and LocalOutlierFactor with saved-state checks, Canvas controls
  and weighted-pipeline row alignment. Joint outlier inference preserves request
  rows with exclusion reasons; LOF distinguishes training from novelty scoring.
- Add fit-time regex/dtype/exclusion column selection, hierarchical multi-column
  GroupImputer fallback, learned group deviations, cyclic/local-time date
  features, independent Count/TF-IDF vocabularies per column, per-column
  Winsorize percentiles, RFECV and sequential feature selection. Expose target
  encoder CV/shuffle/seed, MinMax clipping and Robust unit-variance options.
- Reject misspelled preprocessing choices, malformed ordinal orders and invalid
  hash widths instead of silently using fallbacks. Standardize new HashEncoder
  defaults on eight buckets, exclude targets from automatic polynomial expansion,
  and normalize missing TargetEncoder category identities for new fits.
- Keep floating sentinel-to-null replacements numeric. Interpret constant
  imputation text in each selected column's numeric/Boolean type with explicit
  errors for invalid or lossy values. Improve schema previews without guessing
  engine- or data-dependent output types.
- Version new FeatureMath operation validation and nullable calendar outputs;
  previously saved unversioned operations retain their replay behavior. Keep
  existing arithmetic null/zero rules and exact integer clipping boundaries.
- Document tested built-in alternatives beside custom Bundle teaching examples,
  including differences in missing values, output names and dtype handling.

- Add explicit ordered string categories and optional `column_names: slug` to
  `OneHotEncoder`, including Canvas controls. Fixed vocabularies produce stable
  columns even when a training split lacks a category; legacy saved encoders
  retain their original names and behavior.
- Compute context-dependent SHAP preprocessing before sampling explanation rows,
  preserving lag/rolling history and exclusion counts. Row-independent pipelines
  retain early sampling and the same SHAP budgets.
- Raise an explicit error when a saved `GeneralTransformation` power transform
  cannot apply, instead of silently substituting raw values for the whole column.
  Previously saved pipelines that relied on that fallback now fail explicitly.
- Return an unknown preview schema for `GroupImputer` automatic numeric selection,
  whose selected columns depend on observed binary/constant values; explicit
  column selection is unchanged.
- Raise the SHAP `explainability.max_features` guard from 50 to 100 so wider
  models, such as fixed one-hot feature sets, can be explained.
- Add optional `initial_scoring: from_now`: the first batch records a Delta
  checkpoint without predictions, subsequent batches score new inserts, and
  model changes/recovery preserve the original boundary. `full_snapshot`
  remains the default. Normal rebuilds reuse saved prediction keys and recent

- Generate `config/sources.sql` only when setup selects `include_source_sql`;
  the source guide and read-only source checks remain available in every project.

### Upgrade steps for generated Databricks projects

A generated project records its release in `deployment/requirements.txt` and in
the first lines of its README. Before raising that pin from 0.9.3, in order:

1. Package and validate replacement models with this release before upgrading
   jobs that load saved models. Models pickled against the removed flat-module
   import paths can fail to load.
2. As the monitoring store owner, run `initialize_monitoring_store` once. It adds
   the retraining-request table and the `complete_observations`,
   `monitoring_identities` and `serving_windows` views, and refreshes
   `model_version_details` with `training_summary_json`. Producers without
   creation privileges fail until this has run.
3. Grant dashboard viewers SELECT on the three new views.
4. Review each rollout `maximum_latency_ms`. It now limits p99 execution time
   when recorded, instead of the maximum.
5. Raise the pin and redeploy, in one change, every job that shares a model's
   lifecycle tags. Older readers and downgrades reject the new timestamped events.
6. The dashboard definition is a file copied into the project. To adopt the new
   one, replace `src/monitoring/monitoring.lvdash.json` with the file from a
   project generated with this release, after step 2, then deploy. It no longer
   has the Execution and compute page.
7. Optional, for links in the final report's **Where to look** table: add
   `workspace_host: ${workspace.host}` to the `training_report` task parameters in
   `resources/train.job.yml`, and `display_html=globals().get("displayHTML")` to
   the call in `src/jobs/training_report.py` (`models_report.py` for model sets),
   as in a newly generated project. Without them the report still runs; links
   appear as plain text.
8. Add the `allow_unloadable_champion` train-job parameter (default empty) and pass it
   to the lifecycle tasks, as in a newly generated project, so a champion from the
   previous release can be replaced.
9. Optional: add `bundle_target: ${bundle.target}` to the `daily_rollout` task
