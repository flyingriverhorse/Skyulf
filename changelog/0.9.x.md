# Changelog — 0.9.x Series


For the version index, see root [CHANGELOG.md](../CHANGELOG.md).

## v0.9.1

- Databricks projects can select Spark pyfunc inference independently of bounded
  pandas training. Certified Linear/Logistic Regression pipelines with supported
  imputation/scaling and independent model sets retain keyed, distributed Delta
  publication, CDF receipts and monitoring handoffs. Worker packages include the
  exact source wheel; unsupported fitted behavior fails before publication.

- Raise security floors for Sentence Transformers, JupyterLab, Notebook,
  Tornado, urllib3, and virtualenv and refresh their locked versions.
  Sentence Transformers now requires 6.x: local models containing custom
  Python modules no longer load through the default untrusted path.

- Databricks scoring supports pre-split reuse, custom rules, or their ordered
  combination, with an independent switch to skip target-dependent steps.
  Templates explain both phases and include missing-value, numeric-range and
  prediction-band examples, commented out by default in both custom rule lists.
- Databricks project models can save exact external dependency pins and bounded
  declared assets, with fresh-process and MLflow replay checks.
- Optional saved scoring policies produce keyed exclusion reasons and typed,
  versioned business outputs; Delta receipts preserve coverage and progress even
  for all-excluded batches. Training/holdout evaluation stays independent.
- Explicit row filters now select the same eligible evaluation population in
  ordinary fits, tuning, CV, and nested threshold selection. Held-out reports
  disclose input, scored, and excluded rows; empty eligible splits report an
  unavailable evaluation. Filtered branch merges without shared row lineage
  fail explicitly. Serving still preserves requested row alignment.
- Distribution drift now requires both a practical effect threshold and
  sample-aware statistical evidence, with Bonferroni correction across valid
  feature tests. Numeric data uses KS; categorical data uses chi-square or
  exact Fisher tests. Tiny samples can report insufficient evidence rather
  than drift or health; there is no universal 100-row rule. Monitoring preserves
  this evidence in reports, and automatic retraining requires current evidence.
- MLflow local pipelines and model sets now transport nullable signed integers
  and Boolean inputs losslessly, restoring their fitted dtypes before feature
  engineering. `prepare_pyfunc_input` prepares native pandas requests; Spark
  callers cast the declared columns to strings before Arrow conversion. Nulls
  still follow the saved cleaning policy, and integers above `2**53` stay exact.

### Added

- The existing Databricks project template now includes the shared monitoring
  dashboard and one-owner setup helper. Producer enrollment and scheduled
  monitoring create missing owned storage and reuse compatible existing tables
  and views without replacing data. Single, competition and model-set projects
  reuse one dashboard. Overview adds distinct model/table counts, model-to-table
  mappings and daily drift/performance-check trends. Current drift/quality and
  saved performance summaries appear above historical charts; monitoring
  registrations are explained as environment/project/model identities.

- Monitoring Overview separates drift/data-quality health from version-bound
  performance-policy results. Missing or stale evidence stays unavailable;
  an older successful check cannot make a changed enrollment appear healthy.
  Enrollment details live on Drift and data quality with the long identity column
  hidden; detailed performance evidence stays on Model performance.
- Configured Databricks monitoring jobs refresh the native AI/BI dashboard after
  measurement and retraining evaluation. A target-specific helper preserves
  development bypass and creates no email subscription. Execution views show
  classic-node CPU/memory utilization with explicit unavailable serverless values;
  performance checks distinguish measured loss from actual training requests.
- Native monitoring performance page shows latest batch counts and coverage,
  a compact policy decision, independent baseline comparison, and classification
  evidence. Missing latest evidence stays unavailable; single chart points remain
  visible. Generated Databricks projects omit six unreferenced legacy notebooks;
  public library entrypoints remain compatible.
- Generated Databricks monitoring jobs show `monitoring_report` and
  `evaluate_retraining` tasks. Reports separate feature drift, measured model
  performance and baseline-based performance loss, and explain disabled or
  report-only policies. Either eligible signal can request one guarded retrain;
  legacy notebook entrypoints remain compatible.
- Native monitoring dashboard selectors use independent option sources and
  accept NULL defaults, so blank selections no longer hide model choices or
  matching observations. Performance policy evidence stays visible when the
  selected chart metric differs from the policy metric.

- Databricks monitoring can calculate quality, drift, labeled performance and
  training-data freshness on Spark without the local observation row cap. New
  Bundles use a separate monitoring job with delayed-label revisits and prepared
  version-bound references; shared Delta results feed the native AI/BI dashboard.
  Generated scoring jobs call it through a visible native Run Job task. The
  dashboard separates monitoring contexts, shows saved classification confusion
  counts and adds job-scoped execution and estimated list-price cost views.

- Databricks monitoring supports independent, default-off performance policies
  with pinned baselines, mature labels, minimum coverage and consecutive windows.
  Reports and dashboards show degradation and request outcomes; automatic
  retraining shares the existing fresh-data, cooldown and duplicate-request guards.

- Databricks Bundles prepare a version-checked Core wheel during deployment and
  record its SHA-256; content-specific wheel build tags prevent stale serverless package
  reuse after source changes. Shared runtime requirements include selected Optuna and
  optional model/ensemble dependencies plus project preprocessing/scoring pins;
  training-only requirements retain optional SHAP/chart packages. Compute settings,
  worker bounds, job tags and serverless budget policies support target overrides.

- Databricks Bundle classifiers support optional `off`, `manual`, and `auto`
  decision policies, disabled by default in single, competition and multi-target
  model files. Automatic thresholds use a separate training calibration partition;
  CV and competition score the complete policy on independent outer folds.
  Saved models retain binary positive-class decisions and multiclass scaled argmax.
  Split membership and threshold metrics reuse Core helpers.
  Original target labels survive LabelEncoder/OrdinalEncoder, resampling,
  threshold selection, registry reload and holdout evaluation; users do not
  need to supply internal class codes.

- Supported supervised models accept training row weights through Core
  `sample_weight` and optional weight columns declared in Bundle model files. Weights follow actual
  train/CV/refit rows, can combine with existing classification `class_weight`,
  and stay outside model features and scoring inputs. Saved training evidence
  records aggregate weights and source/row digests. Row filters, deduplication,
  outlier removal and lag/rolling transforms preserve positional alignment.
- Voting, stacking and calibration support sample weights when every receiving
  base/final estimator supports them. Random sampling transports source weights;
  synthetic sampling uses an explicit class-mean or uniform weight policy.
- Bundle single, competition and multi-target projects expose the same weight
  column setting in their model files, with independent multi-target branches.
  The optional wizard flow filters models using Core's shared capability check;
  no separate `weights.py` hook is generated. Model parameters remain the place
  to edit `class_weight`; fixed values are preserved by default search spaces.
- The canvas Class Weight control preserves a real null when switching from
  Balanced to None, including the submitted training configuration.

- `GroupImputer` preprocessing node fills missing values from each row's own
  group (mean, median or most frequent), learned on training rows only, with an
  overall fallback for groups unseen in training. On the canvas it is the
  **Group Imputer** method of the Imputation node.
- `ClipValues` preprocessing node caps values at fixed bounds without dropping
  rows, so the same caps apply at prediction time. On the canvas it is the
  **Clip to Fixed Bounds** method of the Outlier node.
- Canvas validation flags a missing `group_by` column, and clip bounds cannot
  reference a target already separated from the features.

### Changed

- Personal Databricks development targets skip central model enrollment and
  monitoring, drift and automatic retraining tasks. Shared deployments keep their
  monitoring flow, while development training and scoring handoff remain active.

- Databricks model sets can promote when at least one component meets its
  improvement requirement and no component regresses on its selected metric.
  Equal peers are allowed; all-tied sets remain challengers. Absolute quality
  gates and whole-set activation, approval and rollback checks still apply.

- Databricks Bundles support daily rolling training windows with a selected
  source event column, project-level drift thresholds, and an optional visible
  `retrain_on_drift` task. Fresh eligible target data, current observations,
  quality checks, durable request deduplication and cooldown guard requests to
  the existing train job; training and approval policies remain unchanged.
  The Job graph shows eligibility and an explicit true/false condition: eligible
  requests recheck the guards before submission; skipped requests show the reason.

- Databricks evaluation images are published in parameter-free `Charts` child
  runs, preventing long training-parameter headers in native image grids.
  Single, competition and model-set reports link to these children while
  preserving training metadata and reading metric summaries from their source runs.

- Databricks monitoring enrolls models when they become active and runs
  a separate `monitor_model` task after scoring. Independent model projects share
  a central Delta inventory and AI/BI dashboard; retries preserve active model
  selections and avoid duplicating successful observations.
  New Bundles enable monitoring by default and require a central destination;
  an explicit false setting pauses it. Drift and quality use separate tables
  with per-metric limits. Drift charts show feature PSI against its own limit
  and counts of affected features over time. Performance uses dynamic metric
  columns, explicit true outcome counts, a latest-measurement bar chart and
  a time series for a selected model/version/metric.
  Generated scoring jobs expose a separate `drift_report` task after monitoring;
  monitoring/report output links to the configured shared dashboard. Drift-count
  charts show full monitoring timestamps and timezone instead of abbreviated hours.
  Multi-target activation and scoring now enroll each pinned component, preserving
  its parent set/version and shared physical output table. Monitoring repairs skip
  only completed component observations; the drift task displays each component.

- Databricks Bundle setup can opt into bounded SHAP explanations with explicit
  training dependencies. Training notebooks and MLflow artifacts show global
  importance and signed sample waterfalls. Competition runs retain the selected
  child's explanation evidence on the parent without recomputing it.

- MLflow training Parameters also show fitted model defaults and selected values,
  ensemble members and internal settings, active holdout controls, and ordered
  preprocessing/pre-split recipe summaries. Complete summaries are saved in
  `training_parameters.json`; project recipe names travel with the saved pipeline.

- Databricks training runs expose tuning budgets, seeds, strategy settings, search
  spaces and selected model parameters in MLflow Experiments Parameters, including
  competition candidates and multi-target branches. Large values retain a pointer
  to the complete `tuning.json` artifact; requested and actual trial counts stay
  separate. Nested CV displays the final search's selected parameters.

- Generated Databricks model files use `single_model.py`, `model_competition.py`
  and `multi_model.py`, with plain Python dictionaries for model/search settings.
  Single-model JSON stays empty until the Python declaration is loaded; saved-model
  actions keep using persisted evidence without executing editable training code.
  Legacy file names remain supported, conflicting definitions fail explicitly,
  and the generated wizard schema uses compact formatting with unchanged prompts.

- Databricks Bundle initialization now generates each model's own ensemble params,
  tuning controls and editable Core-derived search space. Multi-target setup creates
  independent branches with target, recipes, CV and quality settings. New projects
  omit shared `ensemble.py`/`tuning.py` hooks; existing hooks remain supported.
  Offline preview displays branch settings, and CI checks generated search catalogs.

- Databricks projects can compare named standalone and ensemble candidates for
  one target with shared CV and bounded per-candidate tuning. A deterministic
  leaderboard selects one winner for registration; existing holdout gates,
  approval, rejection and rollback govern its champion status. Candidate recipes
  and saved custom preprocessing are kept with their MLflow run evidence.
  Bundle setup now selects 2-8 task-compatible candidates and shared search,
  preprocessing and per-candidate ensemble settings, generating editable candidate
  recipes automatically. Each ensemble has its own base-model menus, voting weights,
  stacking controls and optional calibration. Offline preview displays every candidate.

- Databricks wizard schema sources are split by topic and generate the committed
  CLI schema. CI and pre-commit detect stale output; existing prompts and defaults
  are preserved.

- Model sets now nominate `challenger`, retain displaced `previous_challenger`
  history and support explicit `reject` with a durable reason. Approval clears
  the promoted challenger; rollback preserves unrelated contenders. Rejected,
  stale and uncontrolled candidates cannot bypass the shared alias protocol.

- Newly registered Databricks model-set versions show component count and each
  branch's registered model name, pinned version and estimator type as inspection tags.

- Databricks model sets support opt-in automatic activation with independent saved
  component quality gates. Manual approval enforces the same limits; replacement
  compares each model with its counterpart in the pinned champion set. Failed
  gates preserve the active set, and successful quality evidence is verified on rollback.

- Pin the imbalanced-learn compatibility dependency to `sklearn-compat==0.1.5`:
  version 0.1.6 breaks geometric-mean (`g_score`) evaluation with imbalanced-learn 0.14.1.

- Halving searches cap sample-resource maxima to each search's training population,
  including smaller nested folds. Impossible explicit minima still fail and
  estimator resources such as tree counts retain their configured limits.

- Model-set scoring can rebuild results and temporal history after source
  UPDATE/DELETE with `source_change_policy=rebuild_on_change`, using the existing
  atomic batch rebuild. Insert-only appends remain unchanged; legacy projects
  still reject corrections unless explicitly enabled.

- Multi-model scoring keeps model rules and combined business rules together in
  `features/scoring.py`. Bundle setup selects all results, combined results only,
  or named model/business views over one atomic Delta publication. Custom output
  names preserve deployment ownership; saved models retain their original rules.

- Multi-target Databricks projects can package a complete versioned model set,
  explicitly approve or roll back its champion, and score through the existing
  score job. Saved components and composition rules join by record keys; each
  rule declares its required models. One atomic Delta publication preserves set
  provenance, exclusions and temporal continuation, with append or full rebuild.

- Multi-target branches select named preprocessing and pre-split recipes
  independently from shared feature code, with selections preserved during
  saved-model and training-plan replay. Setup hides model-specific questions
  for this layout. Asset manifests now support inline usage instructions and
  a `files` list while retaining the original list format.

- Optional Databricks multi-target training uses one pinned Delta snapshot with
  independent labels, features, model recipes and evaluation policies. Sequential
  branches retain linked MLflow runs and immutable model versions, with saved
  plans for reproducible fresh-run replay and explicit partial-failure evidence.
  Single-model training remains the default.

- Lag and rolling preprocessing now offer opt-in bounded temporal history.
  Immutable artifact seeds, per-entity continuation, chronological fold refits
  and row-order preservation are shared by pandas and Polars. Backend prediction
  can return explicit continuation state; Databricks incremental publication
  commits history together with predictions and its source watermark. Canvas
  exposes the history choice. Existing batch-only behavior stays the default.

- Generated Databricks projects organize notebook entrypoints under `src/jobs`,
  feature recipes under `src/features`, model hooks under `src/modeling`, and
  offline preview under `src/tools`. Pre-split and learned preprocessing have
  separate builders and configurable custom steps. Feature packages preserve relative
  imports and all Python source in the model snapshot, including fresh-process
  MLflow reloads. Legacy single-file projects remain supported; external package
  dependencies still require explicit installation.

- Reusable custom completeness filtering and training-only frequency encoding
  live in `pre_split_custom.py` and `preprocessing_custom.py`. Their parent recipes
  show custom steps directly in their ordered lists alongside Core operations.
  Both support pandas/Polars and saved-model replay. Removed the redundant
  external preprocessing example files.

### Fixed

- Core predictions now return original encoded-target labels consistently with
  saved artifacts; threshold declarations preserve the original class type.
  Boolean, integer, float and NumPy scalar declarations are no longer
  interchangeable (`True` or `1.0` cannot select integer class `1`).
  Fixed-model nested CV reports all evaluation metrics, undefined classification
  metrics expose reasons, and CV aggregates report valid and total fold counts.
  Generic SHAP explanations use the configured default seed.
- Raw preprocessing through `StatefulEstimator.fit_predict` now requires explicit
  `preprocessing_sample_weight` when the processed dataset carries weights,
  preventing positional reuse after rows have been filtered or reordered.
- Univariate selection defaults to the inferred task and rejects classification
  statistics for regression targets. Polars robust scaling
  retains Float64 precision, and numeric date features require a saved explicit
  `epoch_unit` (`s`, `ms`, `us`, or `ns`), including refits of ambiguous old
  artifacts. Similarity features retain their fitted backend and reject a
  missing required backend instead of silently changing feature values.
- Profiling compares equivalent datetime instants across units and timezones,
  bounds ill-conditioned VIF regression work, and requires three finite shared
  observations for target correlations. Decimal profiles preserve source values;
  approximate Float64 analytics are unavailable when conversion loses observed
  distinctions. Monitoring keeps KS p-values diagnostic.
- Registered MLflow loaders select the registry's artifact copy. A definitely
  refused first alias write releases its pending marker only after unchanged
  aliases and an aborted receipt are verified; uncertain outcomes remain locked.
  Local prediction artifacts omit retained training weights without mutating
  the live pipeline.
- Databricks repeated-shuffle admission uses its actual validation size, automatic
  calibration preserves external evaluation splits, and delayed monitor enrollment
  cannot replace a newer model-set parent with the same component version.
  Guides clarify group fractions, validation/CV precedence and native class weights.
- Core packaging requires setuptools>=77.0.0 for SPDX license
  metadata, and published README links resolve outside a source checkout.

- Monitoring enrollment keeps its bounded memory capacity separate from larger
  training/scoring allowances. Future label revisions no longer block metrics
  for already available labels; eligible duplicates and transfer limits remain errors.
- Resampling preserves exact selected integer values and avoids repeating sampling
  when replaying split datasets. Validation stratification is checked independently;
  native numeric sample weights avoid per-value Python validation.
- Profiling uses finite observations without losing original row identities.
  Integer drift preserves small changes at large magnitudes and handles Int128 safely.
- Polars group aggregates preserve key identity, H3 rejects invalid coordinate
  ranges, Box-Cox reports excluded columns, and polynomial output avoids deprecated joins.

- Nullable pandas columns retain exact values during positional assignment,
  pandas subclasses resolve their own engine, and weighted resampling preserves
  the input target format. An absent threshold policy can be explicitly `None`.
- Binary threshold dictionaries honor their class key; multiclass tuning rejects
  binary-only grid search. Ensemble switches require booleans, and cross-validation
  accepts list targets with preprocessing and row weights.
- Fitted power transforms honor sklearn output settings in Polars. Division keeps
  negative near-zero signs, generated features reject ambiguous names, and lag
  features consistently read original source columns.
- Weighted Databricks competition jobs use the selected model names throughout
  their task graph. Policy names and cost tags retain quotes and backslashes in YAML.

- Target encoding handles repeated missing labels, integer casts reject exact
  overflow boundaries, and Polars profiles count NaNs as missing. Simple and
  general transformations accept numeric text without narrowing native numbers.
- Profiling retains the target within capped correlation matrices and preserves
  row metadata when all columns are excluded. Unsupported Object statistics stay
  unavailable, including duplicate counts in the UI. Decomposition filters retain
  large integer labels; Boolean text casing no longer creates false drift.
- MLflow tracking observes asynchronous failures and rejects artifact traversal
  under both Windows and POSIX paths. Pyfunc restores matching pandas nullable
  types without integer rounding; MLflow still rejects null Int64/boolean inputs
  before the adapter runs. Model-set scoring preserves native Polars Date inputs.

- Supervised feature selection accepts list and NumPy targets and rejects missing
  classification labels before factorization. Empty sentence-embedding batches
  retain their fitted columns; weekend features preserve missing dates.
- Profiling flags categorical and Boolean constants, plots constant measurements
  without KDE failures, and releases its figures after rendering errors. Temporal
  trends retain partial observations, and numeric class labels respect an explicit
  classification task in rule reports.
- Model-set packaging rejects record keys reused as component features. Empty
  Databricks full rebuilds preserve saved date, timestamp and categorical schemas,
  categorical PSI appears in drift reports, and refreshing renamed model branches
  preserves notebook paths and SHAP task references.

- Tuning leaves caller-owned estimator defaults and search spaces unchanged.
  Direct time-series searches sort training rows and exclude the time column
  with or without weights, while temporal-history policies keep their metadata.
- Project function steps validate outputs against the original row index even
  when callbacks edit their private frame. Learn callbacks receive a writable
  target copy, preserving the caller's training labels.
- Local pipeline artifact format 2 binds the saved threshold choice to the
  payload checksum and registry identity. Version 1 artifacts with fitted
  thresholds require re-export; artifacts without fitted thresholds remain readable.
  Every new export uses the new payload structure and receives a new digest;
  references pinned to an earlier export must use that export's original digest.

## v0.9.0

Target: optional Spark execution and MLflow integration for Skyulf Core.
Development version: 0.9.0. This release has not been published; Spark node
execution, MLflow registry and Databricks delivery remain under development.

### Changed

- Databricks training graph now separates data loading, fixed preparation/split,
  training/tuning, candidate selection, registration, comparison and decision.
  Approve/reject/rollback share the decision task; the final report checks task
  success before scoring. Checked Parquet artifacts carry bounded datasets
  between tasks. Candidate selection currently reports one model; graph-2
  bundles keep their existing runtime path.

- Nested tuning now runs independent inner searches within outer training folds,
  with preprocessing refit inside each fold and a separate final model search.
  Optional inner-fold controls and saved outer evaluation results are connected
  across Core, Canvas and Databricks. Search budgets apply per search. Nested temporal and group policies preserve
  boundaries at both levels, with explicit gap/window controls and split metadata
  excluded from features. Binary nested thresholds use training-only inner OOF
  predictions and persist an independent final threshold for artifact replay.
  Bundle CV questions now precede the data window; temporal selection opens the
  required clock/window fields and omits unused shuffle/seed prompts.

- Logistic Regression preserves explicit L1/L2/Elastic Net/unpenalized settings
  on older scikit-learn runtimes. The newer `l1_ratio`/`C` translation is applied
  only when the installed estimator uses that API, keeping tuning refits and
  ensemble components consistent with the requested penalty.

- Databricks quality-gate model-version tags now use Unity Catalog-compatible
  names. Post-selection ensemble CV removes the completed tuning control while
  preserving the selected component parameters.
  Automatic halving spaces leave the selected resource to the scheduler, and
  saved-model actions no longer expand editable training search recipes.

- Databricks ensemble recipes live in optional `src/ensemble.py`, separate from
  common search configuration. Named weights, calibration, stacking meta-learners
  and fixed component parameters are validated without silent Core fallbacks.
  Hard voting now supports prediction-only local artifacts and matching MLflow/SDK
  schemas. SGD is available as an ensemble component, matching the Canvas picker.

- Databricks setup now selects a Core tuning strategy directly, with automatic
  model search spaces, task-specific models/ensembles and default/custom controls.
  Shared CV refits preprocessing within training folds, preserves final holdout
  isolation and saves selected parameters/trials. Optional `src/tuning.py`
  overrides and bounded SHAP evidence are captured with the fitted artifact.
  Standalone tuning now prepares ensemble members and excludes temporal ordering
  metadata from required inference inputs; halving forwards resource bounds.

- Databricks model comparison supports optional absolute `quality_gates`
  alongside one selection metric. First champion and manual approval enforce
  every gate, with per-gate notebook/MLflow evidence and unchanged historical
  single-gate receipt hashes. Comparison validation and decisions now use
  focused helpers with explicit absolute-improvement semantics.

- Databricks lifecycle tasks restore saved custom preprocessing registrations
  before validating the training specification or running CV in a new process.
  Pinned recipes remain authoritative across task boundaries.

- Generated Databricks scoring uses a fixed `run_score_notebook` entrypoint
  without a training artifact directory. The role-based notebook API remains
  a compatibility adapter; fixed lifecycle phases and SDK APIs are preserved.

- Generated Databricks projects now carry a shorter setup/operator README and
  minimal preprocessing hooks. Custom Calculator/Applier tutorials live in the
  shared examples directory; saved single-file code remains replayable. README
  graph-contract instructions now match the generated lifecycle tasks.

- Databricks basic setup now uses defaults for advanced snapshot/split, sampling,
  CV and policy details, reducing default prompts from 33 to 26. Existing init
  files retain their values and validation; the setup guide explains overrides.

- Databricks comparison/decision tasks avoid a discarded source replay and reuse
  verified comparison metadata within its phase. Registration still rechecks its
  receipt immediately before mutation; decision retains fresh evidence and
  membership checks before alias changes.

- Databricks evidence and training-spec validation now use focused helpers;
  lifecycle completion and failure handling are separated while preserving
  validation order, durable receipts and original errors.

- Databricks lifecycle replay and approval now share saved training-spec parsing
  and verified evidence loading. Common result construction lives in the workflow
  layer, removing the task adapter's notebook dependency while preserving imports
  and operator/scoring output.

- SDK and durable Databricks training now share policy/CV validation, source and
  champion preparation, and bounded registry tags. Task receipts, SDK callbacks
  and existing champion compatibility checks retain their execution boundaries.

- First-candidate notebook reports now render a missing champion's null metrics
  as "No champion", preserving readable comparison and approval/rejection output.

- The Bundle lifecycle graph now has eight tasks: training/evaluation/registration
  and comparison/promotion each share a task. `finalize_and_report` joins both
  branches with `ALL_DONE`, closes failed training, and publishes a score request
  only after verifying successful saved evidence. Redundant edges and standalone
  bookkeeping notebooks were removed; the two serialized jobs are preserved.

- Bundle training uses one `train` action for manual and cron invocations;
  `train_monthly` has been removed. An unset `training_version` resolves the
  latest source snapshot once, while explicit versions remain pinned. Data
  windows remain independent of schedules, and explicit result cutoffs are
  preserved. Regenerate existing scheduled jobs with the matching wheel.

- The local Bundle exposes preparation, training/registration and comparison/decision
  as real tasks in the same serialized lifecycle job.
  Manual actions bypass training; tasks share pinned MLflow artifacts and
  verified phase evidence. Training finalization is independent of scoring,
  and the final decision/operator inputs appear in `finalize_and_report`.
  Regenerate the graph and notebooks with the matching wheel (graph contract 2).
  Lifecycle repairs/retries are rejected until uncertain effects are inspected.

- Local candidate training records its pinned source/window and original pipeline
  input in MLflow before reading data, splitting, CV or fitting. Runtime failures
  retain replay evidence on a FAILED run without publishing a model. Manual
  replay uses the original config so fixed cleanup is not prepended twice.

- Bundle training and scoring have independent optional cron, timezone and pause
  settings; selected schedules default to enabled. Rolling temporal training can
  choose its holdout duration, and result filtering can use a configurable delay
  in elapsed UTC hours. Manual replay retains explicit data boundaries.

- Databricks source periods compare UTC instants across repeated DST hours.
  Controlled champion reads verify the committed registry event; concrete model
  versions and registry URI types fail early when invalid. Concurrent MLflow
  experiment creation reuses the winning experiment without hiding other errors.
  Pre-split execution and preservation checks are separated into focused helpers.

- Fixed pre-split admission uses per-node validators and derives its supported
  node set from the same rule table. Validation behavior and errors are unchanged.

- Bundle pre-split recipes support validated fixed cleanup, deterministic
  Deduplicate and explicitly declared custom row filters in `preprocessing.py`.
  Saved models apply feature cleanup once to raw prediction inputs; target-only
  cleanup and training eligibility filters do not require prediction columns.
  Approval restores saved custom code before verifying the recipe and evidence.

- Text vectorizers preserve fitted feature columns and dtypes on empty evaluation
  partitions. TF-IDF and hashing recipes can now train through the local Bundle
  adapter without failing on its empty test partition, on pandas and Polars.

- Local retraining saves versioned cleanup evidence with the recipe, saved Python
  source identity, ordered survivor/train/holdout membership and row counts.
  Automatic and manual lifecycle replay verify this evidence against the model
  artifact; editing the current project file cannot replace its saved recipe.
  Training eligibility filters remain separate from prediction inputs.

- Bundle projects can define `build_pre_split_steps()` beside Python preprocessing
  to filter training rows with Core `DropMissingRows` and `ManualBounds` before
  splitting. Bounded reads and optional source samples stay ahead of cleanup;
  filter-only columns stay outside model inputs. Saved recipes and exclusion
  counts support the same holdout replay during model approval. Scoring does not
  apply training eligibility filters.

- Core lag/rolling now reject a missing declared sort column, and direct lag
  artifacts reject nonpositive/noninteger lags. Known current-target rolling is
  blocked regardless of split placement; backend admission reuses the Core rule.
  Temporal artifacts remain configuration-only, with caller-supplied history.

- Bundle date questions follow user-declared column representation without reading
  source data. Native timestamps skip parsing questions; date-only and text choices
  reveal only applicable format/timezone/midnight rules. Disabled date use, CV,
  scheduling and policy compute hide their dependent questions.

- Generated Bundle notebook tasks disable automatic retries, including the
  separate serverless auto-optimization retries that can register an extra
  candidate after a failed training task. Recovery remains explicit.

- Saved local model evaluation uses sequential joblib prediction to reproduce
  parallel forest metrics during exact registry-evidence replay. Training and
  ordinary batch inference retain their configured parallelism; approval checks
  and receipt digests remain exact.

- Bundle initialization is grouped into data, model, evaluation
  CV, lifecycle and compute sections. Window/split choices, source date parsing
  and training sampling are configurable. A generated offline preview reuses
  job preflight and Core registry metadata; model parameters remain editable
  in workflow JSON and ordered preprocessing in a project Python file.

- Bundle setup accepts comma-separated key/feature names, shows task-specific
  model/metric menus and explains dates, data snapshots, sampling and CV with
  examples. Users can choose the prediction output table name. `scheduled`
  enables the selected training cron after deployment, including dev; arbitrary
  cadence remains independent of data-window selection. Old init files must use
  the new input field names.

- Generated `src/preprocessing.py` defines standard Skyulf steps and optional

### Fixed

- Dummy encoding, missing-column removal and feature selection retain row
  counts when their Polars output has no feature columns. New DummyEncoder
  fits exclude float NaN from categories; saved category mappings keep their
  original replay behavior.
- GroupImputer preserves numeric group-key equality without matching numbers
  to text or rounded/truncated keys. This also corrects existing artifacts
  scored with a different group-column dtype; unmatched groups use the saved
  global fill value.
- New OneHotEncoder artifacts distinguish literal missing-token strings from
  nulls. Older artifacts keep their original mapping and require refitting
  to gain this distinction. ValueReplacement supports list rules and applies
  the existing mapping-key conversion to `to_replace`; OrdinalEncoder accepts
  list targets, including empty holdouts.

- Spark identifier validation tolerates Databricks serverless hiding
  `spark.sql.caseSensitive`, retaining conservative collision checks while
  propagating unrelated errors. The failure was reproduced in a live job;
  the correction passed both inference modes in a real serverless Spark Connect
  4.2.0 job using a Polars-trained model loaded from Unity Catalog.
- Delta batch/admission tolerates the explicit serverless restrictions on
  `REFRESH TABLE` and prediction caching. Identity/ownership reads and
  transactional checks remain active; uncached execution stays distributed.
  Other runtime failures propagate, and classic Spark still refreshes/caches.
