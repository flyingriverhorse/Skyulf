## v0.8.1 — Dual-Engine Correctness: Leakage Enforcement, Parity & Experiments

### 📦 Release

- **Version sync to 0.8.1** (app + frontend): root `pyproject.toml` bumped
  to `0.8.1` and `frontend/ml-canvas/package.json` / `package-lock.json`
  synced via `npm run sync-version`, keeping all three in lockstep.

### 🧠 Core

- **skyulf-core 0.6.1** (`skyulf-core/setup.py`): the audit Tier-3/Tier-4
  core remainder — mixed-engine `(X, y)` dispatch errors (F-27), WOE null-key
  parity with its artifact caveat (F-28), inference row-drop guard (F-18),
  NaN-as-missing parity in `DropMissingColumns` and profiling (F-19/F-20),
  the `missing_threshold` declaration fix (F-22), WOE cross-fitting
  (`fit_transform_train`) with pure-noise leakage regression tests, and the
  removal of the dead `StatefulEstimator.refit()` (F-48).

### 🧪 Experiments — Audit Batch 2 (F-36, F-38–F-42, F-44)

The experiments correctness batch scheduled for 0.8.0 that slipped past it
(recorded in the execution ledger's 0.8.0 row but never shipped). Every fix
landed red-green on `080`. F-43 was already shipped via skyulf-core 0.6.0.

- **F-36** "Best Score" no longer compares runs that optimised different
  metrics under one label. In the comparison table and the parallel-run
  card, `best_score` now expands into one row per scoring metric — labelled
  from that row's own metric (e.g. "Best Score (F1 Weighted)") and starred
  only among the runs that optimised it. ⚠️ **Display change**: selecting a
  basic run together with tuned runs now shows one Best Score row per
  metric instead of a single row labelled from whichever run happened to be
  first.
- **F-38** The threshold-scan dropdown no longer conflates `f1_macro` with
  binary/weighted F1: averaged and threshold-independent metrics fall back
  to the documented `f1_weighted` default instead of being routed onto the
  positive-class F1 scan (up to 0.29 away from the tuned number).
- **F-39** The pipeline diff no longer double-lists every
  renamed-and-modified node: duplicate `NodeDiff` entries (same object
  registered under both old and new node ids) are deduped by identity
  before rendering, also silencing the React duplicate-key warning.
- **F-40** `POST .../thresholds/save` now validates the payload (supported
  metric, non-empty classes, threshold keys exactly matching the model's
  classes, finite values, valid split) and returns 400 for garbage instead
  of persisting thresholds that predict-time silently discards.
- **F-41** The "Cross-Validation" checkbox on the Experiments page now
  actually hides `best_score` (a CV metric) along with the other `cv_*`
  keys.
- **F-42** Artifact coverage for task `'other'` no longer reports
  "unsupported" when the artifact exists — a finished run with the artifact
  now shows as available.
- **F-44** Pipeline-diff change descriptions now quote string values, so an
  int→string coercion renders as `5 → "5"` instead of the misleading
  `5 → 5`.

### 🧹 Cleanup — Audit

- **F-27** Mixed-engine `(X, y)` pairs (pandas X with polars y, or the
  reverse) now fail fast at the dispatch boundary with a clear
  `TypeError`, instead of surfacing deep inside a node as a confusing
  `AttributeError`. Engine-neutral targets (lists, numpy arrays) are
  unaffected.
- **F-28** The WOE encoder now keys null categories as `"nan"` on **both**
  engines. Pandas previously recorded `"None"` while Polars recorded
  `"nan"`, so cross-engine replay (every Polars-trained pipeline is served
  on pandas) silently mapped null rows to the default WOE. ⚠️ **Artifact
  change**: WOE artifacts fitted on pandas before this release carry the
  `"None"` key, so null rows fall back to the default until the node is
  re-fit.
- **F-45** Pipeline diffs no longer report `NaN ↔ null` parameter changes
  as "unchanged".
- **F-46** Confusion-matrix class labels are sorted numerically when all
  labels are numeric (class 2 no longer renders after class 10).
- **F-47** Experiments run IDs widened from 8 to 10 characters to reduce
  prefix collisions between batches.
- **F-48** Removed the dead `StatefulEstimator.refit()` — zero production
  callers; train+validation refit is not a supported flow.

### 🔬 Parity — Audit Batch 3 (F-18–F-25)

The small Tier-3 parity findings, all landed red-green on `081`.
F-21/F-23/F-24/F-26 were verified already resolved by the Polars migration.

- **F-18** Row-dropping steps (`Deduplicate`, `DropMissingRows`) no longer
  re-execute at inference. A prediction request for 4 rows now always yields
  4 predictions (or a visible model error for a null row) instead of
  silently returning fewer predictions than inputs with no way to tell which
  rows vanished.
- **F-19** `DropMissingColumns` on the Polars engine now counts NaN as
  missing on float columns (`is_null + is_nan`), matching pandas' `isna()`.
  Both engines now drop the same columns on NaN-bearing data.
- **F-20** Dataset profiling on Polars no longer reports `missing = 0` for
  NaN-bearing columns while showing `mean = NaN` — frame-level and
  per-column missing counts include NaN on float columns.
- **F-22** The `DropMissingColumns` node declaration now advertises
  `missing_threshold` (the parameter fit() actually reads and the frontend
  already sends) instead of the dead `threshold` key. Declaration-only
  change; no user-facing parameter rename.
- **F-25** Serving now logs a warning when a deployment bundle trained on a
  non-pandas engine receives pandas prediction input — the spot to check
  first if predictions look wrong.

### 🔒 Leakage enforcement (F-16, F-17)

The leakage gate is now single-sourced, fail-closed, and binding.

- ⚠️ **Breaking — `on_leakage` defaults to `"raise"`.** A data-dependent
  preprocessing step wired before the train/test split now **blocks
  execution** with a clear `ValueError` instead of emitting a warning that
  could be ignored. Set `on_leakage="warn"` for the old behaviour or
  `"ignore"` for silence.
- **F-16 — six previously-exempted nodes are now gated.**
  `MissingIndicator`, `DropMissingColumns`, `HashEncoder`, `Deduplicate`,
  `Oversampling` and `Undersampling` all learn from the data they are
  fitted on (missingness structure, drop lists, bucket occupancy, duplicate
  sets, resampled rows); placing them before a split leaks test-set
  structure and is now rejected. Pipelines that relied on the old order
  need to move these nodes after the splitter.
- **Single source of truth.** Every node now declares a **required**
  `learns_from_data` flag on its `@node_meta` (omitting it is a
  registration error), and both the core diagnostic and the backend
  pre-execution gate derive their node lists from the registry. The
  duplicated hand-maintained backend frozenset is deleted — the two lists
  can no longer drift.
- **Fail-closed.** An unrecognised transformer before the split is treated
  as data-dependent until proven otherwise.
- **F-17 — no-splitter diagnostic.** A pipeline with no train/test split
  no longer gets silent "no warnings": it now reports that the leakage
  guarantee does not apply to it (advisory, never blocking).
- **Pure-noise regression test for both target-aware encoders.** WOE
  (cross-fitted on `080`) and TargetEncoder now each have a pure-noise
  target test asserting the leaky full-fit encoding memorises labels
  (discriminative power > 0.75) while the cross-fitted training rows stay
  near chance (< 0.60), on both engines. This test would have caught the
  original WOE leak.
- **`validate_leakage_safety` is a declared public export** (added to
  `skyulf.__all__`; the docs already referenced it as a top-level API).
  The [leakage-proof example](../docs/examples/leakage_proof_pandas.md) was
  re-run end-to-end against this release — every documented number and
  assertion still holds.
- **Canvas gate is now registry-driven — no more hand-synced TS list.**
  `GET /api/pipeline/registry` now returns each node's `learns_from_data`
  / `is_splitter` flags (plus `aliases`, so every registration spelling
  like `Split` stays recognised), and the frontend applies them to the
  canvas leakage check at startup. The hardcoded frontend lists are
  demoted to a bundled fallback used until the fetch lands or if it
  fails — a node reclassified in skyulf-core now reaches the canvas
  with zero frontend changes.
- **Param-aware gate exemptions for dual-mode nodes.** The gate now
  understands that some nodes only *learn* in certain configurations:
  a `DropMissingColumns` node dropping explicitly named columns (a fixed
  user decision), a `SimpleImputer` with `strategy="constant"` (a fixed
  fill value), a `MissingIndicator` flagging explicitly named columns,
  and a `HashEncoder` given an explicit column list (deterministic
  hashing) learn nothing from the rows and are allowed before the split;
  their data-learning modes — a positive `missing_threshold`, statistic
  imputation strategies, auto-detected missingness or categorical
  columns — remain gated. Enforced identically in the core diagnostic,
  the backend pre-execution gate, and the canvas. A registry-wide audit
  re-checked every node's `learns_from_data` declaration against its
  `fit()` and found no further misclassifications.
- **Core warns before training.** `SkyulfPipeline.fit()` now runs the
  leakage structure check and logs warnings before any fit happens when
  you pass an unsplit frame (leaky ordering, or no split defined at all).
  Fitting on a `SplitDataset` stays silent — that boundary is provided
  externally and enforced by construction.
- **Leakage proofs split per engine.** The leakage-proof example now has
  two labelled twins — `Leakage Proof (pandas)`
  (`docs/examples/leakage_proof_pandas.md`) and `Leakage Proof (polars)`
  (`docs/examples/leakage_proof_polars.md`): same Titanic dataset, same
  split seed, bit-identical artifacts across engines and full
  poisoned-test-set invariance — the guarantee is engine-agnostic.

### 🎨 Frontend — Jobs

- **Job Details CV-metrics toggle**: the metric tile grids in Job Details
  (training results and tuning Evaluation Metrics) gained a "Show CV
  metrics" checkbox that hides the `cv_*` and `best_score` tiles, which can
  crowd out the train/test numbers on tuned jobs. The toggle only appears
  when the job actually reported CV metrics; shown by default.
- **Job Details Related records restyle**: the Related row is now a set of
  consistent icon chips — the pipeline run expands into a full-width card
  with a labelled run-id code block, parent-run/branch and nodes-executed
  chips, and the preview/branch explanation callout. The "Inspect node" and
  "Model version" action chips sit right-aligned and stay put while the run
  card expands. No behaviour change.
- **Job Details leakage gate verdict**: every pipeline run now records the
  pre-execution leakage check's verdict on the job, and Job Details shows a
  "Leakage Gate" tile in the overview — green "Passed" when no
  data-learning node fits before the split, amber "No split" when the graph
  has no splitter, red "Warnings" when issues were logged in warn mode.
  Clicking the tile opens the gate's report for that run: every
  data-learning node it checked and where it sits relative to the split,
  any param-aware exemptions allowed before the split (with why), the split
  boundary, and the gate's messages. Jobs run before this stamp existed
  simply omit the tile; older verdicts without the structured detail fall
  back to showing the recorded messages.

## v0.8.0

### 📦 Release

- **Version sync to 0.8.0** (app + frontend): root `pyproject.toml` bumped to
  `0.8.0` and `frontend/ml-canvas/package.json` / `package-lock.json` synced
  via `npm run sync-version`, keeping all three in lockstep for this release.

### 🧠 Core

- **skyulf-core 0.6.0** (`skyulf-core/setup.py`): the Growth initiative
  Wave 2 core release — null/NaN semantics fixes (F-01, F-04, F-05, F-06),
  lag/rolling stale-`y` fix (T1), `"variance"` alias (T2), `"uniform"`
  alias (T3), the registry contract test suite (T5), and datetime coercion
  (T6), **plus the Audit Tier 2 remainder (F-07–F-14)**:
  - **F-07** `OrdinalEncoder` missing-value encoding now identical across
    engines and dtypes (`NaN`/`None`/null all collapse to one `"nan"` key).
  - **F-08** `GeneralBinning`/`CustomBinning`/`KBinsDiscretizer` Polars
    apply now treats out-of-range values as missing, matching pandas.
  - **F-09** `SkyulfPolarsWrapper` frames no longer crash dual-engine nodes;
    the dispatcher unwraps before and rewraps after every Polars step.
  - **F-10** pandas nullable `Int64`/pyarrow numeric columns no longer crash
    imputers or Winsorize (upcast to float64 like Polars does natively).
  - **F-11** `HashEncoder` uses one deterministic blake2b hash on both
    engines. ⚠️ **Buckets will change**: artifacts fitted with the Polars
    engine before this release map categories to different buckets after it;
    refit before serving.
  - **F-13** Drift detection no longer silently reports "no drift" when the
    data contains `NaN` (NaNs are excluded before computing statistics).
  - **F-14** `WOEEncoder` gained the `fit_transform_train` cross-fitting
    hook `TargetEncoder` already had. ⚠️ **Scores will change**: training
    rows are now encoded out-of-fold, so previously inflated training/CV
    scores on small or high-cardinality categoricals will drop toward their
    honest value (on a pure-noise target the leaky encoding measured at
    ROC-AUC ≈ 0.79 vs the true 0.50).

### 🐛 Bug Fixes — Backend

- **F-12** Polars clustering deployments no longer advertise non-numeric
  columns the model was never fit on: the bundled `feature_columns` now
  reuses the exact numeric filter the clustering fit applies, so the
  deployment API and manual-prediction routes accept the right inputs.

### 🚀 Backend — Polars

- **`SKYULF_ENGINE` setting** (default **`polars`**): one explicit,
  env-configurable switch (`polars|pandas`, case/whitespace-insensitive,
  unknown values rejected at startup) now governs the DataFrame engine the
  backend runs on. Polars is the platform default; pandas remains a
  first-class, explicitly selectable option.
- **F-25 engine provenance**: the engine a model was trained on is no longer
  a guess. Deployment bundles record it (detected from the actual training
  frame) in both the FeatureEngineer and legacy bundle formats, and training
  and tuning job rows record it in `job_metadata` — so a
  trained-on-polars/served-on-pandas mismatch becomes detectable instead of
  silent. The Jobs UI now shows it too (engine tile in job details, Polars
  badge on job cards).
- **Polars ingestion (Phase 2)**: dataset reads now honor `SKYULF_ENGINE`.
  With the polars default, CSV/parquet are read natively by Polars
  (full-file schema inference, so nullable-integer columns keep their `Int64`
  type instead of silently becoming strings); JSON/Excel and S3 source reads
  convert to Polars after the pandas read. The pipeline's ingestion guard now
  accepts Polars frames under `SKYULF_ENGINE=polars` and still fails loudly
  on any engine mismatch or non-frame input.
- **Polars floor raised to 1.43.2**: versions below it mis-infer a nullable
  integer column as `String` when the empty field sits at the end of a CRLF
  line — silent dtype corruption on Windows-authored CSVs. ⚠️ Upgrade
  polars if you pin your own environment.
- **Phase 3 — pandas-only assumptions removed** (migration plan §Phase 3):
  the pieces of the engine that silently assumed pandas now handle the
  configured engine's frames natively:
  - **F-31** drift-reference data is saved for Polars-trained jobs again —
    `_normalize_train_frame` returned `None` for Polars payloads, so the
    reference artifact was never persisted and drift detection had nothing
    to compare against.
  - **F-32** feature importances resolve for Polars training frames
    (`_feature_names_for_importance` was pandas-only, so the Experiments
    page's Feature Importance tab rendered nothing).
  - **F-30** the deployment input schema no longer labels Polars-typed
    columns "unknown": `_pretty_dtype` now recognises Polars dtype strings
    (`Date`, `Duration('us')`, `Categorical`, `Enum`, …).
  - **F-43** (skyulf-core) the clustering reference crosstab no longer
    invents a `"nan"` segment when a float reference column contains NaN —
    Polars treats NaN as a valid value, not a null, and `pd.crosstab`
    drops it; both engines now agree.
  - The drift consumer (`/monitoring` reference-data load) accepts a Polars
    reference frame directly instead of assuming pandas.
  - Engine-boundary plumbing: the pandas-only internals (merge logic, SHAP,
    data-preview stats) convert at their boundary and hand back the
    configured engine's frame type, so a `SKYULF_ENGINE=polars` pipeline
    stays Polars end to end. Column resolution dedupes requested columns —
    Polars' `.select` raises where pandas silently duplicated.
  - Full backend suite passes under **both** `SKYULF_ENGINE=polars`
    (default) and `SKYULF_ENGINE=pandas`.
  - **F-26 dead-code removal**: Polars is a hard dependency, so the
    unreachable `HAS_POLARS` "polars not installed" fallbacks are gone —
    `PolarsEngine` self-registers unconditionally and `DataService` no longer
    branches on availability.
  - **Engine docs**: `docs/guides/engine_mechanics.md` now documents the
    `SKYULF_ENGINE` switch (polars default, pandas first-class, provenance
    recorded).
  - **Category B round-trip removal** (migration plan Phase 4): the nodes
    that converted the **whole frame** to pandas and back inside Polars
    `apply` are now Polars-native —
    **H3Index** (cell indices computed from the two coordinate columns only),
    **EllipticEnvelope** (boolean mask from numpy, native `filter`),
    **TrainTestSplitter** (`train_test_split` on row indices + native
    `gather`, including validation and stratified splits), and the five text
    nodes — **Count/TF-IDF/Hashing vectorizers, Tokenizer, SentenceEmbedder**
    (text pulled as `list[str]`, encoded output attached via `hstack`;
    non-String text columns fall back to the pandas path for `astype(str)`
    parity). Resampling stays pandas-bound by design (imblearn).
    - Side effect that matters: Polars inputs keep their exact dtypes end to
      end — the round-trip silently upcast nullable `Int64` to `Float64`.
      Guarded by new red-green dtype-preservation tests on every site.
    - Measured in `skyulf-core/benchmarks/bench_roundtrip_removal.py` and
      published in `docs/performance.md`: splitter **2.79x**, elliptic
      envelope **3.47x**, count vectorizer 1.13x (transform-bound) on
      500k/200k-row frames.
  - **Engine comparison benchmark** (migration plan Phase 5 obligation):
    `skyulf-core/benchmarks/bench_engine_comparison.py` runs the same
    fit+apply for 18 preprocessing nodes and 4 model fits (incl. XGBoost)
    on identical 200k-row pandas vs Polars frames, with fully-specified
    realistic configs (n-grams, stratified train/test/validation splits,
    quantile binning, unknown-handling encoders, 50-tree models) — and
    verifies each node with a **parity check** (both engines' outputs
    compared value-for-value before any timing is reported). Data-munging
    nodes win up to **~106x** (SimpleImputer), HashEncoder 4.9x,
    MinMaxScaler 4.6x, TrainTestSplitter 1.7x; sklearn/XGBoost-bound nodes
    (vectorizers, model fits) land at ~1.0x — no meaningful penalty
    anywhere. Full table in `docs/performance.md`.
